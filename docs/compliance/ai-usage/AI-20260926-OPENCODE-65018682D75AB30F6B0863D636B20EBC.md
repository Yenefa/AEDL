### 实际运行的验证（原文结果）

- `hydra --version` → `hydra 0.6.1` / `Copyright (C) 2026 Javad Rajabzadeh` /
  `License GPL-3.0-or-later`（据此登记 RES-012，不猜测）。
- `where.exe hydra` → `C:\Users\<user>\AppData\Local\Programs\Hydra\hydra.exe`。
- T1 Range 探测：GitHub release 资产 `http=206`、`Accept-Ranges: bytes`、总长 111161483 → PASS。
- T2 `hydra --inspect` → 报出 size/type 且不落文件；对 `speed.cloudflare.com` 报 `Resumable: no`。
- T3 `--fail`：404 → **exit=1** + `server answered 404 Not Found`；正常 URL → **exit=0**。
- T4 `--checksum` 错 hash → **exit=1** + `checksum MISMATCH: the delivered bytes are not the bytes requested`。
- T5 `--checksum` 正确 hash（实算 `eef10c4b…d1c19eb`）→ **exit=0**。
- T6 `-c` 续传：文件被截断至 50 MiB（52428800 B）→ `resumed_from=52428800`，
  终尺寸 178473080，`ok=true`，**exit=0**。
- T7 **服务端忽略 Range**（`speed.cloudflare.com`）→ **exit=1**、`ok=false`、
  `note: server ignored Range and sent 200 for a request from offset …`；证伪了"hydra 会自动退化为单流"的原设想。
- T8 `--preview` 32.6 MB ZIP → 列出 2521 个文件、**exit=0**、仅取回索引（首跑因管道截断误显 exit=1，
  重定向到文件后为 0 → 记为 F6）。
- T9 `--json` 失败报告：原因为 stdout JSON 的 `ok=false` / `note=…`，**stderr 实测 0 字节**。
- T10 `--inspect --json` → 仍输出人读表格，`--json` 未生效。
- 基准（同一 URL，178473080 B，交错各 2 轮）：curl 22.92 s / 7.79 MB/s、hydra 11.65 s / 15.55 MB/s、
  curl 13.70 s / 13.02 MB/s、hydra 15.62 s / 11.54 MB/s。**两组数据重叠，方差 ≥2 倍**。
- 旁证：同期 curl 拉 GitHub release 资产仅约 34 KB/s（300 s 得 10 MB，测试中止）。
