### 缺陷（由 PR #78 的 C4-P6 qualification 发现，不在验收卡内修）

被验对象 `tools/akcli_adapter.py` 存在**校验顺序缺陷**：`symbol_digest`、运行中 akcli 版本、以及实际安装分布的 digest，都在 `_verify_effect()` 里比较 —— 而 `_verify_effect()` 是 **native writer 执行之后**才调用的。同一实现里 `akcli_version`（manifest 声明值）却在写前由 `toolchain_manifest()` 拒绝，两者安全等级不一致。

后果：宿主 manifest 的 `symbol_digest` 与实际不符时，真 writer 仍被启动并**成功改写 stage 文件**（`tool.exit_code = 0`），之后才报 `TOOL_ERROR`。即「在已知 toolchain 不匹配时先写一刀再说」。

合同依据（`docs/competition/internal/AEDL_PR1_实现合同_20260907.md`）：
- L355：Phase 固定 `PRECHECK → SNAPSHOT → STAGE_APPLY → DELTA_CHECK → KICAD_VERIFY → COMMIT`；
- L369：PRECHECK 职责含「校验 Proposal/context/path/file manifest/**toolchain**；native before 全量读取」；
- 且 native write 属 STAGE_APPLY，**只调用一次**。

因此凡能由 (manifest + native before) 定案的 toolchain 身份属性，都必须在 writer 启动前定案。

### 本次改动

- `tools/akcli_adapter.py`
  - 新增 `_verify_toolchain_binding(toolchain, native_before, tool)`：比较**运行中** akcli 版本、已安装分布 digest、`symbol_digest`，返回 reasons。
  - `apply_stage()`：在 `native_before` PASS、写入 `result["native_before"]` 之后、**`_execute_route()` 之前**调用它；不匹配 → `TOOL_ERROR / REPAIR_TOOL_UNAVAILABLE` 并**直接返回**（writer 从未启动）。
  - `_verify_effect()`：移除已前移的三条比较，**只保留**「已安装分布 digest 在 before/after 两次读之间发生变化」——该条本质上只能在写后观测，注释已写明理由。
  - 失败类别与 reason code 相对修前**完全不变**（`TOOL_ERROR` / `REPAIR_TOOL_UNAVAILABLE`），变的只有发生时点。
- `tests/test_akcli_adapter.py`

  - 新增桩用例 `test_an_akcli_that_changes_between_the_two_reads_is_a_tool_error`：守护**被保留**的跨读检查。
