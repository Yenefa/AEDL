### 非门禁性质：这是本轮最重要的性质

**证据状态不能改变轮次命运。** 三种状态端到端实测：

```
MATCH        status=None terminal=False   走到 KICAD_VERIFY
SUBSTITUTION status=None terminal=False   走到 KICAD_VERIFY（不采信任何证据）
                                    两者 status 完全相同
```

`kicad_verify_evidence` 从不向调用方抛异常，也不表达「可以继续」的意见。
工具**只在 MATCH 时执行** —— 用一个无法识别的二进制采集的证据不是关于设计的证据。

**单元测试无法验证这一点**（钉住的 writer 在测试解释器上不可 import，
每轮都停在 STAGE_APPLY），所以它只在真实端到端里断言。这一点在 PR 里写明。

### 被拒绝的轮次不采信 KICAD_VERIFY 证据

端到端里我一开始断言「被拒轮次仍应采集证据」，**失败，而代码是对的**：
DELTA_CHECK 失败的轮次在 `refuse()` 就返回了。对一个已被自己 delta check 判退的
stage 跑 ERC，产出的是关于**被拒产物**的证据，而「被拒轮次上 ERC 跑过了」
正是会被读成「这个修复被检查过」的那句话。已把断言改成相反方向并记录理由。

### 过程中的自造错误（如实记录）

1. `write_text(newline=)` 是 Python 3.10+，测试解释器是 3.9 → 改 `write_bytes`。
2. **stub 的 PDF 分支**：`b"%PDF-1.7..." % run` —— `%P` 不是合法的 bytes 格式符，
   直接抛异常，pdf 行带回一条 Python traceback 而不是文件。
3. **stub 的 netlist 不依赖输入**：写死字符串，所以「改设计 → netlist 变化」
   无法测试，那条测试**因为错误的原因通过**。已让 netlist 带上输入字节数。
4. **空字符串环境变量到不了子进程**（实测：设 `""` 子进程看到 `None`），
   所以「无违规」用 `""` 表示时，stub 回落到默认三条违规，测试**在断言默认值**。
   改用哨兵 `"none"`。
5. **禁 fallback 的测试连错两次**：先 monkeypatch `board_review.find_kicad_cli`
   断言未被调用 —— 但 `repair_pipeline` 从不 import 它，**这个 patch 根本不可能被观测到**，
   属于永不可能失败的测试；改成断言整个模块不含 `board_review` 后，
   又被**我自己解释规则的 docstring** 绊倒。最终形态：用 `ast` 剥掉 docstring，
   断言「无 import 语句」+「工具解析函数体内无禁用名」。
6. `timeout_seconds` 我先假设是嵌套 mapping，实测是**普通 int(60)** ——
   假设错误会静默回落到 120 而不是遵守声明的 60。
7. e2e harness 的 timeout 设 120，而冻结上限是 60，被 `validate_host_binding` 拒绝。

第 4、5 条与前几轮同型：**我写了只在自己脑子里成立的夹具，然后拿「测试绿了」当证据。**
