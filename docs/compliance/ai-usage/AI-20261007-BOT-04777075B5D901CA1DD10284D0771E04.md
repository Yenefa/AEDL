### 起点（实测，不是推测）

评估结论把"DC-06 的公开输入包含答案标签"列为评测阻塞第一条。本机复核成立且比描述更严重：

- `DC-06/placement.json` 的 `labels` 数组与**被扣住的** `native_labels.json` **10/10 逐字相等**，
  而 `episodes_v1.json` 把该文件登记为 `public_input`；`tools/repairbench.py:_llm_arm` 把整个
  文件原样塞进**两路** LLM 的 user prompt（`user["placement_record"]`），
  即 `baseline_generic` 与 `aedl_contract` 都拿到了 oracle 侧才会施加的网名。
- DC-06 的 `fault.kicad_sch` 中 `USB_DP` / `USB_DM` / `USB_DP_CONN` / `USB_DM_CONN`
  出现次数为 **0**；对照：DC-01/DC-03 各 3～5 次、DC-09 删掉一个标签后仍剩 2 次、
  DC-07/DC-08 的 `GND` 29 次。**所以公开输入不只是"有帮助"，它是答案的唯一公开来源。**
- 该 episode 当时在 headline 分母内（`in_scope_v0_1: true`，`solvable_from_frozen_source: true`），
  而 2026-10-05 台账把它写成 "land DC-06 as a **solvable** in-scope episode"——
  这条可解性主张的来源就是被污染的公开输入。
- 原有护栏是装饰：`test_published_placement_is_not_an_answer_key` 只查**键名**
  （`expected` / `answer`），不查内容；而且它所在的类在缺写入器的主机上整类 skip，
  CI 从未执行。同类的 `test_duplicate_in_scope_episodes_are_rejected` 也因整类 skip 而从未在 CI 跑过。
- 顺带查出**动作集合**不一致的实现缺陷：`_llm_arm` 对两路都硬编码
  `strict_nets=ARM_GUARD["aedl_contract"]`，读的不是本路的键。当前两路取值恰好都是 `True`，
  所以没有行为差异，但回执里 `net_split_guard` 按本路记录、实际施加按 `aedl_contract` 记录，
  一旦两路取值不同就会静默错配。

### 修法

1. **边界上强制**：`repairbench_synth.public_placement()` 以白名单
   （`PUBLIC_PLACEMENT_FIELDS = ("components", "pin_points_nm")`）投影，`_llm_arm` 只把投影结果
   交给模型——即使将来某个夹具又塞进答案，也进不了 prompt。选白名单而非黑名单：
   新增字段默认是私密的。
2. **剥离已入库夹具**：`DC-06/placement.json` 删 `labels`（保留被授权的放置槽与引脚坐标），
   `manifest_v1.json` 同步 `sha256 cc7f6b22… (1869B) -> fcb37aba… (729B)`；
   写入保持 CRLF 以匹配该目录既有字节基线（`git show` 证实入库 blob 为 CRLF 114 行）。
3. **DC-06 处置**：`in_scope_v0_1: false`、`solvable_from_frozen_source: false`，
   `scope_note` 写明测量数值与理由，并显式拒绝 `ORACLE_BACKFILL`
   （对齐 `notes/y4/DC06_INPUT_GOVERNANCE_INCIDENT.md` 的同名先例）；
   `answer_key_policy.public_input_policy` 把"公开输入只授予几何"成文。
4. **回执可审计**：`run_arm` 对被逐出的 episode 把 `scope_note` 写进结果 JSON——
   分母悄悄变了却无处可查，是最难事后发现的一类失真。
5. **护栏可失败且在 CI 真跑**：新增无门禁类 `EpisodeGovernance`（5 项）与
   `LlmArmInputGovernance`（3 项），并把只读夹具的查重测试从写入器门禁的类里上移。
   判据：发布字段 ⊆ 白名单；公开输入不得重复任何 oracle 网名；**计分 episode 的答案网名
   必须出现在线原理图里**；被逐出者必须写明理由；两路 LLM 各用本路 guard；
   baseline 只拿 `defect_hint`、AEDL 只拿 `frozen_contract_rule`。
6. 修正失实文档：`synthesise_fault` 原写"public record … without any answer key"，
   模块头原写"with no answer key involved"——两处都按上述事实改写；形参 `placement` 更名 `record`
   并明确 `repair()` 消费的是私密记录（4 处调用全为位置参数，已核）。
