- **根因（已实测确认，不是推断）**：`add_net_label` **静默忽略 `at` 字段**。
  把冻结板与修复板的 label 坐标（整数 nm）做集合差，修复后新增的两片是
  `+3V3 (1270000, 6350000)` 与 `BOOT (1270000, 6350000)`，

- **这一条解释了此前全部失败**：几何本来正确（F1 已钉死）、器件身份忠实（pin UUID 一致）、
  label 数量与 `scope` 都对，唯一错的是 label 被放错了地方。

- **更正上一节的判断**：第六节 F4 写的「akcli 与 verifier 之间存在语义鸿沟」**过重，现更正**：
  不是语义鸿沟，是 **`add_net_label` 的 `at` 参数不生效**这一处具体缺陷。

- **verifier 的归属规则（读源码得到，非猜测）**：
  `_source_partitions` 里 `label_points - set(positions) - wire_points` 非空即报
  `label cannot be uniquely attributed to a pin`。即 label 合法当且仅当
  **它的点等于某个引脚点或某条 wire 的端点**；引脚点为
  `(position[0]+def["point"][0], position[1]-def["point"][1])`，整数纳米，Y 轴翻转。

- **由此得到的关键行为差异（易踩）**：`place_component` 的 `x_mil`/`y_mil` **生效**
  （R9 确实回到本体坐标且 pin UUID 与冻结板一致），但 `add_net_label` 的 `at` **不生效**。
  **不能把 place 成功类推到 label 成功。**

  归属条件是 `引脚点 ∪ wire 端点`，所以**先用 `add_wire` 从 R9 引脚拉一小段正交线，
  再把 label 放在该线端点上**。`add_wire` 的 `pts` 实测是被真实施加的（rc=0），
  这条路径**不依赖 `add_net_label` 的 `at`**。
