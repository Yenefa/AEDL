### 开工探针发现的**前置缺陷**（本卡意外收获，值得单列）

在建立「实际新增对象」集合时实测发现 `tools/akcli_adapter.py` 的 `source_objects()` **没有按 C2 `observe_source` 的口径实现**：

1. 它把整个 `.kicad_sch` 当成一个顶层节点遍历，因此 native 观察的 `source_objects` **永远只有 1 条**（文档根）。实测 DC-04 真实文件有 **114** 个顶层对象，native read 只报 1 个；
2. 字符串原子未去引号，身份带字面 `"` 字符（`"\"a1dbe1c3-…\""`）；
3. 后果：当前实现下「实际新增对象」恒为空集，**对应关系根本无法建立**；且 native 观察的 `source_objects`/`semantic_ast_sha256` 用的是与 C2 不同的 AST 编码，跨 reader 不可比。

修法：改为复用 verifier 的纯 source helper（`_source_ast` / `_source_children` / `_source_value`）遍历**文档子节点**、身份取自 `uuid` 子节点（已去引号）、AST 编码与 C2 一致。

### 发现并上报的边界问题（不在本卡静默处理）

1. **私有名耦合**：`tools/akcli_adapter.py` 现在 import `gates.repair_verification` 的 `_source_ast` / `_source_children` / `_source_value`（私有名）。这是为了让 native 与 source 观察**共用同一套 source 编码**（此前各写一套正是缺陷根因），但如需正式化，应在合同层给这三个 helper 公共名 —— 属合同决定，本卡未改 `gates/**`。
2. **`root:<kind>` 身份**：无 `uuid` 子节点的顶层对象身份为 `root:<kind>`，永远不可能出现在回执的 UUID 集合里；按「严格一致」口径这类新增对象也会阻断（fail-closed）。当前 M2 资格夹具不触发此情形，已文档化。
3. **契约边界**：本卡只闭合「回执 vs artifact」的对应关系；独立 delta / protected 仍归 verifier 与后续 pipeline。

2. **blocker — 新安全保证的事实源未绑定到同一份 bytes**：`read_native()` 用 worker 上报的 `source_sha256` 给 **host 自己重读**的字节盖章，`_assemble_observation()` 因此能产出「components 属 revision A、source_objects 属 revision B」的混合观察 —— 而本轮新增的 `actual_new = after_objects - before_objects` 正以这份观察为唯一事实源。已补两处闭环：① `read_native()` 中 `hash_bytes(host_raw) != payload["source_sha256"]` → `BLOCKED / REPAIR_SOURCE_UNBOUND`，且**不交出不绑定的观察**；② `_verify_effect()` 要求 `native_before/after.source_sha256` 等于本事务的 `before/after_source_sha256`，否则 `BLOCKED / REPAIR_SOURCE_UNBOUND`，且在任何 delta 推导**之前**返回。`REPAIR_SOURCE_UNBOUND` 是合同 §7 已固定的 reason code（`tools/repair_pipeline.py` 亦有 `REASON_SOURCE_UNBOUND`），非新造。附带修正：`read_native` 的 `BLOCKED` 原被 `apply_stage` 折叠成 `UNKNOWN`，现按原失败类传播（新增 `_native_failure_status`），否则 REPAIR_SOURCE_UNBOUND 会被降级成无法据以行动的 UNKNOWN。
3. **gap — C2↔C4 平价缺显式回归**：本卡之所以存在，前置原因就是 `source_objects` 曾报 1 而 C2 报 114 却长期未被发现。已补两例（identity / kind / `semantic_ast_sha256` 逐一致）：普通套件直接比对 `adapter.source_objects` 与 `gates.repair_verification.observe_source`；opt-in 真工具比对 `read_native` 的观察与 `observe_source`。**实测细节**：`normalize_observation` 会对 `source_objects` 排序（`gates/repair_verification.py:256`），故普通套件按 identity 建映射比较，原生一例两边均已归一化、可直接比序列。
