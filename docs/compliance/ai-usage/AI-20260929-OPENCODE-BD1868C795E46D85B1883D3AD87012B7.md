### 为什么是 P0：先量，再建

我没有照着描述直接写，而是先量了三件事。

**一、真实板子的 ERC 长什么样。** 真 `kicad-cli 10.0.5` 跑
`src/hardware/m2-board/m2_board.kicad_sch`：

```
violations            : 39，severity mix {'warning': 39}
error 严重度          : 0
ignored_checks        : 4（single_global_label、four_way_junction、
                            simulation_model_issue、footprint_filter）
included_severities   : ["error", "warning", "exclusion"]
netlist               : 21 个元件、29 个网络
render                : m2_board.svg
drc                   : 0 violations / 0 unconnected / 0 parity
```

**零 error，三十九个 warning，四项被工具自己声明为跳过。** 所以这块板子上
`ERC=0 → PASS` 会放行一块有 39 个 warning、4 项检查被关掉的板子。「零错误」和「干净」
之间的距离，**完全落在 `ignored_checks` 与 severity 分布里**。

**二、`limits` 不需要发明机制。** KiCad 自己的报告顶层就有
`ignored_checks` 和 `included_severities`。ADR-014 早就指定了这两个字段，我上一轮
记为"已记录未实现"——**工具一直在报，流水线一直在丢。**

**三、原代码到底坏在哪。** 四个位置，都有行号：

1. `verify_stage` 结尾 `result["status"] = "PASS" if invariants else "UNKNOWN"`
   —— **生产者就是裁决者**。
2. `_DEFERRED = {name: "NOT_RUN" for name in _DEFERRED_CHECKS}`
   （`repair_verification.py:1624`）是**常量**，只写一次，`:1817` 拷进结果。
   没有任何地方写入真实 ERC 结果 —— **ERC 证据在结构上无法存在**。
3. `:2016-2018` 的 PASS 不变式要求每一项 `deferred` 都等于 `NOT_RUN`
   —— **PASS 主动禁止 ERC 跑过**。
4. `repair_pipeline.py:1067-1069` 拒绝任何不是 `NOT_RUN` 的 `deferred_checks`
   —— **schema 禁止调用方提供它**。

结论（这就是 P0）：**一轮事务只有在「验证根本没发生」这种退化情况下才可能到达
`COMMITTED`。** `COMMITTED` 本身是实现且可达的（`repair_pipeline.py:5143`），
`CommitReceiptTests` 也真的把一轮驱动到它 —— 但 writer、delta 裁决**和 verifier
全部被 stub**，`_run_with` 自己的 docstring 就写着这件事。

### 我自己写的代码里，也有 Owner 拒绝的那个 bug

第一版 producer 用了 `--exit-code-violations`，然后用 `exit_code == 0` 判断
「跑完了」。**跑真实板子立刻暴露**：

```
带 --exit-code-violations : exit 5（39 violations，报告已保存）
不带                      : exit 0（同样 39 violations，报告已保存）
```

也就是：**「工具认真跑了并发现问题」被报成「工具失败」，而只有一块什么都不报的板子
才看起来成功。** 这就是 `ERC=0 → PASS` 换了副面孔 —— 退出码当成了裁决，而不是证据。
我拿真板子跑才发现；读代码不会发现。

修法两条，都写进代码注释：命令**不带** `--exit-code-violations`（退出码因此只表示
「跑了没有」），`completed` 由**产物存在且能解析**决定，退出码**记录而不解释**，
violations 一律从报告的 severity 分布读。变异 M4 专门盯这条。

### 关键结果：默认 policy **拒绝**这块真实板子

```
REFUSE
  IGNORED_CHECKS_NOT_PERMITTED | the ERC run skipped 4 check(s) ...
  WARNING_BUDGET_EXCEEDED     | 39 ERC warning(s) against a budget of 0;
                               zero errors is not the same claim as a clean board
```

而一个**许可了这四项跳过、并把 warning 预算提到 39+ 的 policy 会 PASS 它** ——
所以这个拒绝是**policy 选择，不是写死的 NO**。这正是「裁决机」与「policy」的区别，
也是 `ERC=0 → PASS` 不足以撑起整个故事的原因。另外：不给 policy → REFUSE；
证据绑定到别的字节 → REFUSE。
