### 端到端跑出一个真实 bug —— 我在注释里声称、代码里没实现的行为

第一版真实拒绝演示立刻失败：

```
status         : ROLLBACK

public projection : EXECUTION_UNAVAILABLE   ← 应为 REJECTED
```

根因：`run_round` 的 `refuse()` 闭包**永远**把 `cause_status` 设为 `status`，
没有传入不同值的位置。而 PR #95 的代码注释里我写的是
「cause_status is BLOCKED … that pairing is what projects this round as REJECTED」——
**注释描述了一个从未实现的行为**。真实 writer 跑一次就暴露了。

为什么仓内测试没抓到：当时只**单独**测了 `_feedback_outcome(STATUS_ROLLBACK, STATUS_BLOCKED)`，
没有走 `run_round` 的真实接线。**又一次「测了零件没测装配」。**

修法沿用 M6 的有效做法：把映射抽成可测谓词 `_delta_refusal(verdict) -> (status, cause_status, reasons)`，
并给 `refuse()` 加可选 `cause_status`（默认仍为 `status`，既有调用点不受影响）。

### delta 条目有两种形状，第一版只读了一种

探针发现 `compare_delta` 的条目有两种形状：

- **字段级**（已有对象某字段变了）：`{"field": "value", "before": "10k", "after": "999R", ...}`
  —— `before`/`after` 是**标量值**，`field` 直接给出字段名
- **对象级**（新增/删除对象）：`{"field": "$", "after": {完整描述符}, "before": {"absent": true}}`

第一版实现只按对象级处理，字段级退化成了「被观测但未授权」，**丢掉了字段名和两个值** ——
而这正是标准 5 要的东西。重写后两种形状都正确：

```
字段级： R3 field 'value' was authorized as '10k' but observed as '999R'          object_id=R3
对象级： R9 (new:R9) differs from what was authorized: value authorized='10k'
        but observed='20k'                                                       object_id=new:R9
```

顺带修掉一个观感问题：原本会把裸 UUID 当作 role 印在引用旁边（噪声），现改为
只有 `new:*` 这类合成 role 才展示，已有对象只显示 reference。

### 标准 5 成立的可读性验证

```
section            : components_added
AUTHORIZED  R9 / new:R9 / value=10k
OBSERVED    R9 / new:R9 / value=20k
fields that differ : ['value']          ← 只差 value
```

读者可以直接复述：**「R9 (new:R9) 实际解析为 20k，但授权的是 10k」** —— 不是泛化 ERROR。
且泛化码 `REPAIR_DELTA_MISMATCH` **保留**，完整 verdict 仍在 `receipt["verification"]` 里，
具体 findings 是**增量**而非替换。
