### 触发这个任务的发现

准备 Step 3（COMMIT）时去查 COMMIT 的前提，发现 stage 与 candidate **没有任何强制分离**：

| 事实 | 证据 |
|---|---|
| workspace 合同里没有 stage | `_WORKSPACE_FIELDS = (candidate_root, design_root, repair_root, lock_path)` |
| `run_round` 不知道 candidate 在哪 | 其函数体内 `design_root` / `candidate_root` / `repair_root` 出现次数均为 **0** |
| adapter 也没有 candidate 概念 | `akcli_adapter.py` 中 `design_root` / `candidate_root` 无引用 |

于是「分离」纯属约定。而**我自己的 M6 与 M7 演示都违反了它**：

```
M6/M7: stage_root            = <ws>/cand/design
      host workspace design_root = <ws>/cand/design     ← 同一个目录
```

字节级确认：

| 位置 | 摘要 | 含义 |
|---|---|---|
| 冻结 fixture | `655f585d` | 未被写（正确） |
| M6 candidate design 目录 | `2f660180` | **修复后的字节已在 candidate 里** |
| M7 candidate design 目录 | `45e2e20b` | **被拒绝的未授权字节仍留在 candidate 里** |

所以 PR #95 / #96 的措辞「停在 APPLIED_TO_STAGE，从不 commit」只在窄义上成立
（没跑 commit 阶段），而在「candidate 未被修改」的意义上**不成立**。
两者差别很大，而比赛叙事依赖后者。

### 实现

新增 `_stage_candidate_overlap(stage_root, design_root)`，返回
`equal` / `stage_contains_design` / `design_contains_stage` / `None`（不相交）。
`run_round` 在 **PRECHECK、且在读取 stage 任何字节之前**调用它；重叠即以
`STATUS_BLOCKED` 拒绝，finding 指名两个解析后的路径与具体重叠形态。

两个方向都拒绝，理由不只是「相等」：若 stage **包含** design_root，
adapter 自身的 `_resolve_within` 包含性检查仍允许 op-list 路径伸进 design。
**不相交**才是让「停在 COMMIT 之前」等于「candidate 未被修改」的那个性质。

**fail-closed**：若 host context 没有可用的 design_root，无法证明不相交，
则拒绝而不是默认信任。

### 三个自造错误

1. **两个包含方向写反了。** 我先写成 `if design in stage.parents → stage_contains_design`，
   但 `stage in design.parents` 才表示 stage 是 design 的后代、即 stage **包含** design。
   是**实际运行**分类表发现的，不是读代码发现的。
2. **M6/M7 harness 修正后仍失败**：`design root is not a directory`。
   根因是 harness 原本传 `design_root=str(stage_design.parent)`（旧布局下 stage_design
   正是 `<cand>/design`，其 parent 才是 candidate root）；stage 移走后该表达式不再指向
   candidate。已改为显式传 `cand_root`。**先诊断再改，没有猜。**
3. **S3 的捕获测试名连续猜错两次**（WRONG）。第三次用探针脚本实测出真正失败的是哪两条，
   才命名正确。**变异 harness 自己也会误导，必须实测。**
