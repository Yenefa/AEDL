### 开工探针结论（2026-09-17，真 akcli 0.21.0 + 真 DC-04 资格夹具，只作用在 scratch 副本）

探针先于本卡代码，用于逐条判定「能否用真工具暴露」。四条硬结论：

1. **C4-P5 可原生**：`add_net_label name=GND at=U1.6`。U1.6 是 DC-04 的 `no_connect` 脚（`(no_connect (at 212.09 283.21))`）且原属未命名网络，因此把它命名为 GND 会触碰命名网络，真 writer 在**写入之前**合法拒绝：
   `exit=6` / `error.code=OPLIST` / `"REFUSED: --strict-nets: net split/merge touches a named net; nothing written"` / 字节零变化。
   → 可直接验证「strict 被拒后不得自动改走 exception」+「一次写调用」。
2. **C4-P6 可原生**：真工具照常运行，只扰动宿主 manifest。`symbol_digest` 被扰动 → 真写入 `exit=0` 成功后由 `_verify_effect` 判 `TOOL_ERROR / REPAIR_TOOL_UNAVAILABLE`；`akcli_version` 被扰动 → `toolchain_manifest` 在**任何写调用之前**拒绝（`BLOCKED`，写调用 0 次）。
3. **C4-P7 可原生**：单批 3 op = 恰好 1 次写调用且 `APPLIED_TO_STAGE`；把 DC-04 拆成 `[place_component]` + `[add_net_label ×2]` 两批时，第 1 批单独可落地（字节已变、net_diff 报 `+ NEW <unnamed@R9.1/R9.2>`），第 2 批被真 writer 合法拒绝 —— 拆批与单批**不等价**。
4. **C4-P8 无合法原生路径（本卡最重要的负面结论）**：真 writer 能产生连通性 finding 的形态（悬空 wire；把 `no_connect` 脚真正 wire 起来）都需要 **Operation v1 之外**的 op，adapter 会在**词表**处即拒（0 次写调用）。按判据 §1 规则 2 与 §C4「假红示例」，这条红**不在指定位置**，不能算 P8 的资格。并且实测：用 v1 的 `add_net_label` 打在被 `no_connect` 的脚上（`U1.5`、`J1.A8`），**回执 `connectivity` 与 fresh read 的 connectivity 均为 0 条 finding**（`connectivity.verify` 前后都为空），所以也不存在「v1 op 触发连通性警告」的替代路径。故 P8 只能停在 stub-level，native 记 `NOT_RUN`。
5. **C4-P3 不可行**：走 API 路径需要 E1/E2/E3 原生夹具；仓库只有 DC-01..DC-05（op-list 形态，`tests/fixtures/repair_pr1/native/` 下实测确认）。按卡内约束**不自行造夹具** → `NOT_RUN`。
6. **C4-P2 / C4-P4**：真 writer 在成功路径恒返回 `applied=true` 且 `op_results` 完整覆盖且全 `ok`，因此「字段缺失 / JSON 伪造 true / op 缺项 / 重复 index」无法从真工具观测 → 桩层固定。另有 Observation v1 之外的情形的桩形态。
