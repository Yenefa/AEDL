### F1：评审说的那条之外，还有三条更严重的

评审给了「junction 越界写入」和「哈希遍历」两个方向。我把它跑起来后发现四条：

**1. 跨候选写入。** `_ensure_confined` 拿 `self._root`（整个 workspace）做边界，于是
任何仍在 workspace 内的目标都通过 —— 包括兄弟候选。`mklink /J` 不需要提权。

**2. 内容身份，而且是无声的。** `candidate_hash` 走 `root.rglob("*")`，而 rglob
**会跟随 junction**。实测：

```
hash(candidate-a) 加 junction 前 : cebd096cd88dbcca
hash(candidate-a) 加 junction 后 : c1555a69510bbade
改掉 B 里的文件之后            : 72ecff9007f13e4d
```

所以 candidate-a 的内容身份**取决于 candidate-b 的内容**，没有异常、没有痕迹。这条比
越界写入更严重：绑在 A 上的内容寻址回执会被「别人改了 B」这件事作废，而且两个不同
候选可以被做成同一身份。**关键：解析路径检查修不了这条** —— 遍历不是在逃出边界，是在
走进另一个候选。

**3. ledger 完全没有约束调用。** `record_action` / `get_recorded_action` 直接 mkdir
父目录再打开文件。而 ledger 被**排除在内容哈希之外**，这让它成了放「不是设计内容的
东西」最方便的地方 —— 所以它值得至少和设计文件同等的注意，不是更少。读它还是一次
**泄露**。

**4. 硬链接 —— 解析再比较原理上看不见。** `Path.resolve()` **不跟随**硬链接：两个名字
都是同一 inode 的合法路径，所以「A 里指向 B 的文件」的硬链接解析后**仍在 A 之内**，
比较通过，写入落进 B。实测 `st_nlink 2`、ALLOWED、`candidate-b/victim.json` 变成
`b'WRITTEN-THROUGH'`。同一条路也通 ledger。这是合同 :378 的「文件 link count/别名与
实际身份」在 Sandbox 侧的同一个性质。

### F3：复现了，也把影响范围收紧了（结论：真实缺陷，但影响未证实）

上面原本只有一句转述评审的话。跑完之后有实测，而且**第二半比第一半更重要**。

**复现（真实记录，非读代码推断）：**

```
PASS(seq 1) 然后 FAIL(seq 2) -> _latest_verification_hash 返回 aaaa...（PASS 的哈希）
FAIL(seq 1) 然后 PASS(seq 2) -> 同样返回 aaaa...
```

所以 store 的答案取决于两条记录的**先后**，而不是**最新裁决**。原因在
`trust/store.py:398`：非 PASS 的 `continue` 发生在 `:403-407` 的 sequence 比较
**之前**，于是「latest」其实是「latest PASS」。

**收紧的部分：** 这个 helper **不是死代码** —— 它在 `store.py:458` 被
`assess_promotion` 调用。但它是**陈旧性/身份**检查，不是裁决：它回答「我要晋升的
字节，是不是被验证过的那些字节」。裁决在更早的 `:416` 独立决定，来自
`request.verification_status`，而 orchestrator 在 `orchestrator.py:597` 用自己的
`state["verification_result"]` 构造它，不走这个扫描。所以 FAIL 仍然会通过独立路径
DENY —— **这个缺口单靠自己产生不了一个 ALLOW。**

**未解决、如实标 UNKNOWN：** 上面这个「独立」依赖 orchestrator 的 payload 不比 store
旧，而**没有任何机制保证这一点**：`PromotionRequest.verification_status` 由调用方
提供，`state["verification_result"]` 是状态里恰好带着的东西。所以真正的问题是
「能不能 store 里记了 FAIL、而 state 还说 PASS」。**我没有构造出这样的路径**，也不会
仅凭一个 helper 的名字就把它叫成 P1 —— 那恰好是本条目已经在别处批评过的同一个
错误：接受一个结果而不问它到底在讲什么。

它与 ADR-014 的 `ignored_checks` 同类：一个答案比它看上去在回答的问题更窄。
