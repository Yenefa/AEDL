**B. 十篇论文中决定取舍的具体证据**

**P01 / PCBSchemaGen**

论文使用冻结模型、SKiDL、由数据手册构建并经人工修正的器件知识，以及五层结构验证。其库包含 47 个条目（41 个 IC 与 6 个无源器件），实验为 62 个 PCBBench 和 165 个 OSE 任务。Pass@1 表示一次最多四次调用的轨迹，每题重复运行 15 次；不能解释为单次模型输出正确率。

同样最多四次调用，Gemma4-31B 的独立采样、简单贪心修复、Thompson Sampling 分别为 60.54%、78.40%、81.29%。因此现阶段首先实现简单修复循环比实现 bandit 搜索更值得。这个比较只支持论文所测模型与任务。

单名专家审查 300 个分层抽取样本，其中 150 个被验证器接受的样本有 10 个错误，即接受样本中的误放行比例 6.7%；不能当作总体任务分布的误报率。论文未验证整板 SPICE、热或 EMI；5 kW 案例的布局布线仍由人工完成。

公开 [PCBSchemaGen_v2](https://github.com/HZou9/PCBSchemaGen_v2) 明确提供验证器与 benchmark，未提供完整生成/搜索流程。MIT 已核对。源码 `framework/topo/rule_checker.py` 存在任务配置的 skip_rules、器件类别回退，未知 rule_type 会跳过。因此借用规则原语时，需要加入覆盖检查，去除不适用于交付的 benchmark 特例。

**P02 / DRCY**

可迁移的是按功能分区、资料定位/提取、根因归并和定位到设计页面的反馈。论文描述提取 critic、最多五次资料获取替代、缓存等工程策略；没有给出足以独立评估准确率、召回率和修复收益的受控实验。[官方产品](https://www.allspice.io/product/drcy) 是商业审查助手。没有核实到可作为本期依赖的开源完整实现。

**P03 / PCBWorld**

679 块板是环境数据规模，主要实验实际采用 99 块小板与 10 块中等板，292 块大板挑战没有运行。五次尝试择优；GPT-5.4 交互模式小板完成率为 65%，中等板为 0%，Freerouting 对应为 80%/78%。这些数字不能与原理图或 RTL 的成功率比较。

环境以固定器件位置的布线为核心；少量 Agent 动作不等于全部底层 API。数据预处理对部分制造与 courtyard 规则作兼容性放宽，这些设置不能直接用作生产验收。已读 [PCBWorld 1.0-NC 许可证](https://github.com/LGAI-Research/PCBWorld/blob/main/LICENSE_PCBWorld_1.0-NC.md)，包含非商业、命名及其他限制。比赛使用也需符合其条件，不能按 MIT 类资源处理。

**P04 / CircuitLM**

主要是限定器件库、检索、CircuitJSON 与 SVG。100 个提示、每模型三次实验中，Gemini 的 ERC 通过与 LLM judge 得分分别为 88%/53%，Llama 为 84%/21%。后者仍是模型评价，不能视为真实电路功能测量。全文上下文基线在部分模型上并不比检索方案差。

[公开仓库](https://github.com/Khandakar227/CircuitLM) 的 MIT 已核对；README 将网表导出、闭环、编辑与复核等列为未完成工作。主要借鉴表示与范围控制，不把它当作现成 KiCad 闭环。

**P05 / SchGen**

核心价值是语义引脚和相对位置接口。论文报告 82% 格式/工具有效率，人工功能评估为 60.5%；分布外实验不支持假定其微调模型必然优于较强通用模型。

已核对 [数据分割代码](https://github.com/microsoft/SchGen/blob/main/dataset_construction/dataset_split.py)：当前实现明确按设计分组并检查分组不重叠。因此早期仅根据论文描述产生的数据泄漏疑虑，不能作为已证实缺陷；当前代码与原论文实验分割是否完全相同，未复现。

已读接口关键路径：存在模糊符号/引脚匹配、全局状态，以及 R/C/L 封装被统一设为 0201 默认值的逻辑。这些默认行为与精确器件验收相冲突。MIT 已核对；适合作为必要接口的备选，不能直接搬进交付链。[接口源码](https://github.com/microsoft/SchGen/blob/main/modules/kicad_sch_interface.py)

**P06 / AutoChip**

依赖编译器和预先提供的 golden testbench。论文比较最大调用预算 k(d+1)，反馈收益对模型有差异，GPT-4o 的一致收益不能泛化到所有模型。最佳人工题集结果 84% 与混合模型的 75% 不应被写成同一效果点下的完全等价。

Zenodo 链接本次访问失败，但作者 [AutoChip 仓库](https://github.com/shailja-thakur/AutoChip) 可读取，当前 README 对应所给论文；许可证位于 `autochip_scripts/LICENCE`，为 Apache-2.0。没有复现 RTL 仿真。

**P07 / VeriSure**

209 个任务的 93.30% 指测试集功能通过，不代表整体形式化正确。完整方案 93.30%，去掉 contract 为 90.43%，去掉切片/追踪/补丁组为 82.30%，去掉 formal 为 89.47%；组件交互存在，不能将差值解释为独立因果贡献。

Asserter 主要执行 Verilator 断言仿真；Boolean Proofer 用 SymbiYosys/Z3 针对局部组合逻辑，与由共享合同产生的参考模型比较，时序状态逻辑不在同一证明范围。规格源头也可能共同错误。

附录第 20–21 页经图像核对：将时钟 always 块缺少 else 解释为 latch 不准确；示例 negedge 监视器与上一 negedge 的保存值比较，会受到合法 posedge 更新影响；称作同步复位的修复代码仍含 `posedge areset`。这些问题不证明整篇实验无效，但足以说明不能直接照抄断言或“silicon-grade”表达。[公开实现](https://github.com/xyjoey/Veri-Sure) MIT 已核对，完整流程未运行。

**P08 / HWE-Bench**

所给论文是 300 个板级任务、8 个领域、2,914 份数据手册的工作。人工 golden LTspice 验收条件是值得学习的独立证据来源。表格均值为静态 71.84%、动态 58.65%；第 7 页关于大多数动态表现更高的文字与六个模型的表格不一致。8.15% 的整体指标不能与其他论文成功率直接比较，部分聚合解释不充分。

没有核实到匹配作者与论文的可下载代码/数据。[pku-liang/hwe-bench](https://github.com/pku-liang/hwe-bench) 对应另一个 arXiv 编号及 417 个 RTL/Chisel 任务，不是此论文。不能因为同名就承诺复用板级数据集。

**P09 / PostEDA-Bench**

145 个 IC 物理设计任务，包括 40 个 DRC-Essential、30 个 DRC-Reasoning、35 个单目标 PPA、40 个多目标 PPA。被测最好结果分别约为 85.5%、36.66%、64.56%、20%。任务预算和其他论文不同；复杂 critic、tree-of-thought 并非稳定更好。

DRC 任务没有 LVS；PPA 的功能检查依赖有限测试与时延处理，缺少 testbench 时的跳过不能迁移成 AEDL 的“通过”。[仓库](https://github.com/pengjas/posteda-bench) 与许可证已读，LICENSE 为 CC BY 4.0；未运行 OpenROAD/KLayout 实验。

**P10 / EDAid**

三路候选与模型裁判、ChipLlama 微调提升的是有限 EDA 脚本任务成功率。50+50 个任务中的 100%，与单 Agent 的 94%/96% 差距只涉及少量题，不能推广成工业 PPA 或硬件正确率。

[ChatEDA 仓库](https://github.com/wuhy68/ChatEDA) 可读取且为 Apache-2.0；公开内容主要含训练示例、接口及 benchmark，不应当作完整 EDAid 论文系统交付物。无需为本次竞赛复现其模型训练。

试验只作用于 M2 原理图副本：

| 操作 | 观察 |
|---|---|
| 读取实际 M2 文件 | 成功解析 23 个符号对象、29 个网络；符号数包含虚拟电源标记 |
| C1 的 Value 从 10uF 改为 22uF | 原生文件实际变化；这是操作能力试验，不是获准的电路改进 |
| 重读并比较 | 同一解析器下网络不变、对象数量不变、C1 值已变化 |
| 再执行同一操作 | 修改后文件字节相同 |
| 将 USB_DM_CONN 重命名成 USB_DP_CONN | strict-nets 检出合网并拒绝，退出码 6，字节未变化 |
| 恢复 | 显式 `undo --apply` 后按所需备份深度恢复，最终与原文件字节一致 |

需要特别注意：重复 apply 会影响回滚所需的快照位置；不能假定一次 undo 总能回到修复轮次的基准版本。最初试验也发现命令默认 dry-run，退出码 0 不能单独证明已经写入。最终证据以 `applied` 字段、重新读取和字节哈希共同核对。

源文件原始 SHA256 为 `a13db35036a0629a63f18af5600f60fdfe456d890d462b00b899d84ccc898b58`，试验后源仓工作区保持干净。没有运行独立 KiCad ERC；没有调用 LLM 生成补丁；没有证明电路功能正确。此试验支持“优先接现有适配器”，不支持“自动修复已经完成”。

**F. 官方赛道事实与研究建议的区别**

本次依据主仓引用定位到 2026 第八届全球校园人工智能算法精英大赛官网；“AI赛智云创新赛”这一简称没有被当作另一个已核实赛事。

- [AI+硬件创新规则](https://www.aicomp.cn/tracks/tracks-2/3797.html) 要求围绕智能硬件产品提供算法作用、硬件资料与实测数据；允许调用在线算法或大模型，并非必须本地推理。
- [AI+开源通知](https://www.aicomp.cn/notice/notice-3/4890.html) 和 [规则附件](https://www.aicomp.cn/wp-content/uploads/2026/08/%E9%99%84%E4%BB%B61_AIC%C2%B7AI%E5%BC%80%E6%BA%90%E7%AB%9E%E8%B5%9B%E8%A7%84%E5%88%99%E5%8F%8A%E4%BD%9C%E5%93%81%E6%8F%90%E4%BA%A4%E8%A6%81%E6%B1%820812.pdf) 明确开发工具、测试流程、可复用贡献等方向，拒绝只调用模型、套模板或换界面的简单组合。
- 规则不要求大模型训练、企业级平台、专用硬件或专利。至少一种与核心功能相关的可复用/可核验成果值得准备；当前 private 仓库本身不等于违规，规则允许符合条件的受限提交与开放计划。
- 官网当前列出开源初赛截止 10 月 15 日 20:00；10 月 12 日是本研究遵循的用户目标。
- 约 150 人时、24 个案例、2–3 类修复、选择开源开发工具方向，均为本研究建议，不是官方硬性要求或已取得成绩。

**G. 本轮未解决但没有伪装为已解决的事项**

HWE 板级数据和代码获取；全部论文实验复现；所有候选开源库的全面正确性与集成验证；真实 KiCad/仿真运行环境；M2 U3 的最终供电方案与实板结果；独立用户测试；官方报名系统中队伍的实际状态。这些分别影响后续软件选择、物理可靠性与提交准备，不影响本次基于现有证据作出的范围和赛道建议。
