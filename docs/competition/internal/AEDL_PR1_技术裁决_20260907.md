审查日期：2026-09-07。范围：代码级审查、M2 副本上的原生操作资格试验、下一步工程任务。未实现 AEDL 修复执行器或例外机制，未修改远端仓库、创建 PR、运行 Y4 或签发制造许可。

## 3. 拒绝究竟发生在哪一层

**第一层：操作语法与局部原生编辑。** 0.21.0 有 place_component、delete_object、add_wire、add_net_label 等原语，没有“授权换 USB 端点”或“批准串阻插入”的专用安全命令。M2 当前是局部标签连接、0 条 wire 的原理图，所以 DC-01 可以通过精确删除 U1 两个标签并重新放标签表达；这改变的是实际网络成员，不能冒充纯文本改名。参考 [操作定义](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/opspec.py#L195)、[标签锚点实现](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/writers/handlers/labels.py#L58)。

**第二层：strict 的语义差分门禁。** pipeline/draw.py:94 只有 do_apply && strict_nets 时启用 strict；103–106 调用 netgate.evaluate；108–123 对“无法计算差分”或 net_risk 拒绝。netgate.py:142–146 用重读后的网络调用 netdiff.diff / has_risk。netdiff.py:140–207 按引脚成员交叠分类；210–218 只要 split/merge 任一侧涉及命名网络就判风险。commands/drawing.py:755–758 将拒绝变成 exit 6 错误对象，响应并不含普通 draw-result 的 applied 字段。[draw 门禁](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/pipeline/draw.py#L94)、[差分分类与风险规则](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/netdiff.py#L140)、[CLI 拒绝输出](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/commands/drawing.py#L755)。

因此：

- DC-01：两个旧网各有一个成员留在原网、一个成员移入另一网，必然同时产生 split/merge。
- DC-02：真实悬空 U2.2 被读成独立单点网；接入命名 GND 就是 merge。这已由本轮复现消除 W1 计划中“可能触发”的不确定性。
- DC-03：连接器与 U1 从同一导电网分离到电阻两侧，必然产生 split。
- DC-04/05：同一批次中新器件引脚在 before 图中不存在，加入旧网只记 modified。先单独放置会使新引脚在下一次 before 图中成为单点网，后续接线就成为 merge。

**第三层：writer 自身的完整性检查与原子写入。** writers/executor.py:69–147 保留 op-list 验证、GUI 锁、逐项错误、自动 junction、重新解析、connectivity.verify；任何 op error 或 ERROR/CRITICAL finding 阻止写入，最终调用 atomic_write。atomic.py:80–160 负责读前快照校验、临时文件、fsync、verify、备份与 replace。这层不实施 strict-nets，也不理解获准设计。[原生 writer](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/writers/executor.py#L69)、[原子写入](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/writers/atomic.py#L80)。

不能只保留第三层就声称安全：NO_CONNECT_CONFLICT 在 writer 中只是 WARNING；CLI 的额外 KiCad ERC 也只是 advisory。AEDL 必须把与本次拓扑完整性有关的警告作为阻断项，显式运行自己的独立验证。[NC 警告实现](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/writers/connectivity.py#L738)、[advisory ERC](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/pipeline/draw.py#L159)。

**原版严格模式没有已核实的精确豁免接口。** draw 的真实 help 无此参数；arrange 的 --allow-net-changes 属于另一条重排路径，不是局部修复授权接口。改用不同连线原语不会改变 DC-01/02/03 的前后分区事实。不得通过先删标签、改名、删除/重建组件身份或把危险变更拆成多个调用让 strict 看不到原始分区变化。

## 4. 每项 exact topology delta 与 protected-diff

以下用 N(x) 表示导电网的完整引脚成员集合，不把电阻、电容本体当作理想导线。引脚身份至少绑定 sheet/组件 UUID/ref/pin；网络名需带作用域，不能仅靠显示名识别。未连接引脚保持各自身份，不能把所有 net=null 合并成一个网。

所有“=”都要求集合相等，不能写成“至少包含”。所有案例共同要求：图、组件集合及属性的其余部分完全不变；新对象数量、类型、参数、符号来源和精确落点属于已批准的有限集合。UUID 选择器还要验证类型与唯一性，不接受“对象不存在但工具说 replay-safe”作为首次成功。

### E1 / DC-01：仅交换 U1 侧归属

前置：

- N(USB_DM) = {R8.2, U1.14}
- N(USB_DP) = {R7.2, U1.13}

后置：

- N(USB_DM) = {R8.2, U1.13}
- N(USB_DP) = {R7.2, U1.14}

精确允许：四个 pin→net 归属增删；对应的 2 split + 2 merge 是此交换的派生表现，不单独授权任意四个风险事件。

protected-diff：N(USB_DP_CONN)={J1.A6,J1.B6,R7.1}、N(USB_DM_CONN)={J1.A7,J1.B7,R8.1}；R7/R8 的 22R、符号和封装；其余全部网络、所有 U1 其他引脚与组件身份。不得交换 J1 极性、同时换 R7/R8 身份或通过改符号 pin 定义伪造正确。

fail closed：少换一端、D+/D− 短接、只换标签名称但成员仍错、误删 J1/R7/R8 标签、影响任何额外引脚或无法唯一识别被删对象。

### E2 / DC-02：单点 ADDR 并入 GND

前置：U2.2 为确定的单点悬空输入；不是带其他成员的匿名网，不是已接高电平，也不是一个可随意取消的 NC。固件 DEFAULT_ADDR=0x44。

后置：GND_after = GND_before ∪ {U2.2}，原 U2.2 单点分区消失；无其他新增/移出成员。

protected-diff：原 GND 全体成员之间的关系；U2.1/SDA、U2.4/SCL、U2.5/+3V3、U2.7/8/9 的 GND 关系；U2.3、U2.6 原有未连接/NC 状态；src/firmware/include/sht30.h 及固件依赖字节不变。

本题所用 DC-02 只批准 logic low。高电平对应另一份固件/设计授权，不能把“0x44 或 0x45 都是有效地址”解释成可自行择一。

fail closed：把匿名多引脚网整体并入地、改为 +3V3、只修改固件、ADDR 仍悬空、取消未授权 NC、事实与冻结固件冲突。

### E3 / DC-03：两个独立拆网，恢复真实串联结构

前置：R7/R8 确实缺失；正路导电分区为 {J1.A6,J1.B6,U1.14}，负路为 {J1.A7,J1.B7,U1.13}，二者分离。前图可带该故障已知的两侧名字别名；必须冻结其真实成员和别名，不能猜规范名。

后置四个分区：

- {J1.A6,J1.B6,R7.1} = USB_DP_CONN
- {R7.2,U1.14} = USB_DP
- {J1.A7,J1.B7,R8.1} = USB_DM_CONN
- {R8.2,U1.13} = USB_DM

另要求 R7、R8 都是批准的 Device:R、22R、Resistor_SMD:R_0603_1608Metric，处于实际装配状态；R7.1 与 R7.2 不同导电网，R8.1 与 R8.2 不同导电网；四分区互不短接，不能仍有同名标签/其他 wire 把两侧合回去。

protected-diff：两组 J1 同极性引脚内部关系；U1.13/14 物理身份；其余 U1/J1 引脚；全部非 USB 网络、器件和属性。只准删除经前置检查定位的两个旁路连接对象，不能借 cascade 删除邻近连接。其他故障几何形态必须另外物化并核验，不能套本次两条 wire 的 UUID。

fail closed：只补器件不切旁路、仅修一路、插错极性、33R 替代冻结的 22R、R7/R8 任一端悬空/短接、增加额外串并联件、连接器成对引脚被拆散。

本轮“保留旁路但 strict 放行”的实测负例说明，此项检查是必要门禁。22R 在此是获准基线恢复值，不应说成所有设计都必须如此。[批准基线与案例规则](https://github.com/Yenefa/AEDL/blob/0e84912dd3cd56f1364c7ffc69fd7a9a68ca9ba0/notes/dev-cases/m2-dev-cases-v1.md#L83)。

### DC-04：组合恢复 GPIO9 上拉，无 strict 例外

前置：R9 缺失；BOOT_before={SW2.1,U1.8}；+3V3 是已存在的确定网络。

后置：新增 R9=10k、Device:R、批准封装；+3V3_after=+3V3_before∪{R9.1}；BOOT_after={SW2.1,U1.8,R9.2}。

protected-diff：SW2.1 与 U1.8 的原关系，SW2.2→GND，所有原 +3V3 成员，其他 strapping 引脚与所有非目标网络。R9 两端不得同网，也不得变为下拉。

safe_path：place_component 与两条 add_net_label（或已核准局部 wire）在同一 op-list，一次 strict apply。若当前输入是“R9 已存在但两端悬空”，不再是该 READY 前置状态；不得自动套用缺件分支或悄悄扩大例外。

fail closed：遗漏 BOOT/U1.8 的实际接入、改动按键地端、误用下拉/错阻值/重复 ref、试图把内部弱上拉论据当作“不恢复批准基线”的许可。

### DC-05：组合恢复 EN 电容，无 strict 例外

前置：C5 缺失；EN_before={R3.2,SW1.1,U1.2}，且 R3.1→+3V3、SW1.2→GND、R3=10k 保持成立。

后置：新增 C5=1uF、Device:C、Capacitor_SMD:C_0603_1608Metric；EN_after=EN_before∪{C5.1}；GND_after=GND_before∪{C5.2}。

protected-diff：R3.2/SW1.1/U1.2 三者仍同网；R3.1→+3V3、SW1.2→GND、R3 值和全部原 GND 成员不变；其余电路、固件保持。

safe_path：放置与两端接入同一批 strict apply。不能先形成新的浮空 C5 再第二次接线。

fail closed：C5 两端同网、接错电源、只接一端、R3/SW1/U1.2 任一关系损坏、把 R3 删除后用别的路径凑出 EN 标签。原故障 EN 仍经 R3 上拉，不能报告为“EN 已悬空”。

### 全局 protected-diff 不能缩成已有五条规则

当前 m2_schematic_contract_v1.json 的 EN/GPIO9 检查主要列 C5、R9，不能完整覆盖上面要求的 R3/SW1/U1.2、SW2/U1.8；evaluate_observations 仅比较规则列出的字段。_parse_netlist 又主要保留 pin→net/NC 和组件 value，不能据此宣称封装、符号、UUID 与完整分区均受保护。[现有合同](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/gates/contracts/m2_schematic_contract_v1.json)、[现有检查器](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/gates/schematic_semantics.py#L240)。

新增验证必须保留 fresh KiCad XML 的完整分区；不能先把所有未连接网归为 null 再组网。还须检查全部现存组件、pin 身份、库定义、装配属性和局部连接对象以外的修改。XML 未覆盖的关键属性用只读独立提取或字节不变约束补足，缺失则 UNKNOWN，不猜默认值。项目、PCB、intent、BOM、固件、事实和政策均是冻结只读依赖。本次局部成功不解除 U3 背景 BLOCKED。

## 5. 最小可辩护例外：实现于 AEDL adapter，限定原生 stage 写入

选择 **包一层 AEDL adapter，调用已有 writers.kicad.apply**。不改上游 netdiff.has_risk，不全局关闭 strict，不采用整图生成、自由文本写 KiCad、全局 rename_net 或 arrange 来绕过。

理由：原生 writer 已实测具备这三项编辑能力；缺的是“哪些确切变化获得许可”的判断。writer 是上游公开的 Python 入口，但本轮只对固定 0.21.0 负责，不能假定跨版本 API 稳定。主进程若仍用 Python 3.9，应通过固定的 Python≥3.11 worker 执行，禁止为省事把动态 Python/任意 shell 当补丁内容。[writer 入口及参数](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/writers/executor.py#L69)。

普通分支仍运行 strict CLI；例外分支只用于已绑定 E1/E2/E3 的单轮事务，采用以下顺序：

1. 宿主固定 target、base hashes、工具及库版本、policy digest、事实/授权引用、允许对象与变化；提议器只提供受限 op-list 和诊断。未取得既有权限先拒绝，不能“执行后再找授权”。
2. 检查精确前置图、文件集合、唯一对象、操作/路径白名单；保存固定原始字节快照，建立单写者事务。
3. 在该 candidate 内由宿主生成的独立 stage 中，用原生 writer 执行完整 op-list；它不能直接写被验收的 design 文件。保留全部 op 错误、connectivity gate、GUI 锁与原子 writer；禁止 monkeypatch 这些检查。
4. 读取完整 before/after 图，计算精确 delta。要求实际变化等于获准变化，且 protected-diff 为空；named split/merge 必须恰好是 E1/E2/E3 的派生结果。其他修改即使 strict 原本不拒绝，也不得通过。
5. 在 stage 上执行独立 KiCad 新导出/ERC，以及相同许可下的完整图检查。源字节在验证前后必须稳定；工具失败、零覆盖、旧报告、关键字段缺失或解析器分歧都不接受。
6. 只把已经验证、哈希绑定的 stage 字节原子替换到同一 candidate 的获准 design 路径，重读检查哈希；**不得为了提交再重跑 op-list**。任何失败恢复/保留失败 stage 供诊断，关闭事务。
7. 形成执行回执，后续按现有 VerifierPort / 审核和 promotion 路径处理。局部候选接受不等于制造放行。

这里的例外是替换“命名网 split/merge 一律拒绝”这一项决策，不能称为“仍走原版 strict 成功”，更不能将任意 exit 6 转为成功。writer 不能出错，差分不能不可用，权限不能缺失。

不得使用 CLI 的 net_diff.lines 作为授权数据：format_summary 默认截断到 20 行，modified 单方向最多展示 3 个 pin；NetGate 也不携带完整结构化差分。应读取原生 NetDiff 对象/完整图，并以 KiCad 的独立观察再次核对。[摘要截断实现](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/netdiff.py#L221)。

## 6. Patch envelope 应包含什么

沿用 W1 的 AEDL envelope 包住 akcli protocol 2。以下是待实现的契约字段，不是现有 akcli 新参数。

| 字段 | 约束与来源 |
|---|---|
| schema_version / patch_id / patch_sha256 | 固定版本；ID 与摘要由宿主绑定，重复 ID 不得换内容 |
| decision | PATCH 或 REFUSE；REFUSE 必须无写操作 |
| target | 唯一获准的 candidate 相对 .kicad_sch 路径；不能是绝对/UNC/drive/../链接别名 |
| base.files / base_topology_digest | 实际故障输入和冻结依赖的字节哈希、规范图摘要，由宿主提供并重算 |
| policy_ref + digest / authorization_ref | 指向既有获准范围与静态政策；一个可复制的字符串本身不构成授权 |
| topology_delta | 宿主绑定的 E1/E2/E3 或无例外操作规则；包括 exact before/after memberships、组件增删/属性、完整 protected 投影摘要；不允许通配网名 |
| preconditions | UUID/ref/pin/type、对象唯一性、旧连接/旧参数、组件存在或缺失、期望 NC 与别名 |
| oplist | protocol_version=2、target_format=kicad；限制 ops/字段/数量；禁止 sheets/group 路由、任意 symbol_source、全局改名和 cascade |
| toolchain | 固定 akcli 版本/发行包摘要、Python 运行时、独立 KiCad 版本及库依赖摘要；宿主管理 |
| diagnosis | rule_id、observed、fact_ids、requirement_level、理由；仅用于诊断/B 评价 |
| refusal | 资料缺口、原因与所需人工判断；不得夹带操作 |

组件放置只批准具体 Device:R/C、ref、value、footprint 与落点；参数编辑只允许精确字段。M2 内嵌符号库已足够本轮试验，不需要从网络获取符号。其他环境缺库必须明确失败，不能临时改成“相近器件”。

各层拒绝未知字段、重复/歧义标识、非法数字及过量操作。请求不得含 applied、verdict、verification_pass、snapshot_path、accepted、signed_by 等自证字段。例外值、快照路径、执行身份和候选根目录必须由宿主绑定，不能从模型 JSON 提升为权限。

回执单独记录：branch(strict/exception)、exception ID、patch/policy/source/tool hashes、CLI exit 或 API op/findings、tool_applied（API 没有此原生字段时为 null）、实际 before/after bytes hash、图差分结果、独立 verifier 结果与输出哈希、snapshot ID、rollback 尝试与核验结果、失败层/原因。

CLI 的 applied=true 只是必要条件之一；API 分支不能伪造“工具返回 applied=true”。首次修复要求字节有变且目标成立；无变化只能在已验证的幂等重放条件下归为 NO_CHANGE，不增加修复计数。

## 7. Snapshot / byte-level rollback 与 candidate workspace

现有 CandidateWorkspace 有路径和内容哈希、action ledger，没有不可变文件快照或字节级事务。write_candidate_bytes 使用直接 write_bytes，并非原子恢复；checkpoint 恢复也不是文件恢复。[workspace 实现](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/sandbox_runtime/src/aedl_sandbox/workspace.py#L94)。

最小接法：

- 沿用 run/<run_id>/candidate/<candidate_id>/。只在当前 candidate 下设宿主控制的 design、事务 snapshot、stage、reports 子路径；所有工具写入固定 stage，不接收模型指定路径。
- 轨迹初始快照保存“故障输入”原始 bytes；每轮另存写前快照。不能用正确 golden 文件作为 rollback，否则直接泄露并应用答案。
- snapshot 在启动工具前以不可覆盖方式落盘，保存来源哈希与设计文件清单，验证其内容。快照不在 op-list 可写集合中，不依赖 akcli undo 或轮转 .bak。
- 恢复仅针对已授权写入的设计文件及宿主管理的事务临时文件；发现其他 protected 文件改变就阻断并隔离，不能为掩盖越界继续写本无权限的文件。
- 恢复过程为原始 bytes → 同目录临时文件 → flush/fsync → replace → 逐字节比较及 SHA256 复核。文件集合也核对，不能只恢复 .sch 后忽略额外工程文件。
- 事务未完成标记必须先落盘；进程异常后下次进入先查日志、快照和 live hashes。无法证明 committed 或 rolled-back 就停机；恢复失败为 TOOL_ERROR，保留现场，不继续轮次。
- 重复 patch_id 仅在 patch digest、policy digest 与当前设计/候选清单对应已记录结果时重用回执；hash 漂移阻断，不只信 ledger 命中。重复调用不创建覆盖初始基准的新快照。

两处接口细节必须处理：

1. **候选根目录要再次验证。** workspace._ensure_confined 比较的是整个 workspace root，不是具体 candidate root。候选内链接指向兄弟候选不能仅靠它判定安全。adapter 复用现有 policy.paths.resolve_within(candidate_root, ..., strict=True)，并拒绝待写集合的链接/reparse point/hardlink 别名；这不要求修改 Sandbox 协议或重写 workspace。[现有路径检查](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/sandbox_runtime/src/aedl_sandbox/policy/paths.py)。
2. **设计恢复与 candidate_hash 恢复不同。** candidate_hash 只排除根 .actions.jsonl；.akcli、隐藏快照、stage、报告都会参与。保留失败诊断后，设计字节可恢复但候选整体哈希会变化，不能报告“整个候选回到旧 hash”。固定 design manifest 单独证明 rollback；当前 candidate hash 在全部保留证据写完后重算，不能扩大 HASH_EXCLUDED_INTERNAL_FILES。最后保存的整体 hash 放在既有排除账本/宿主状态，避免自引用。任何后续内容变动都需重新绑定验证。[哈希规则](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/sandbox_runtime/src/aedl_sandbox/workspace.py#L158)。

上游 optimistic snapshot 也不能替代宿主事务锁：strict 预演与真实 apply 是两次读取；writer 的检查在 prepare 阶段，不能独自覆盖整个预演到提交窗口。限定单写者，拒绝 GUI 锁和意外并发，验证结束及提交前后再次核对基准/结果。

若接入正式 Sandbox，仍执行既有 TOOL_EXECUTE、FILE_WRITE、compiler grant 和 VerifierPort 检查；拓扑例外不能覆盖任何 DENY/BLOCKED。现有 _TestOnlyExecutor/_TestOnlyVerifier 是测试假件，不具备 M2 执行资格。[执行政策](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/sandbox_runtime/src/aedl_sandbox/policy/engine.py#L728)、[端口](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/sandbox_runtime/src/aedl_sandbox/protocol.py#L241)。

本轮没有验证断电/磁盘损坏恢复，不应作此保证。

## 10. Go / No-Go

**Go：**

- E1/E2/E3 及对应输入/参数/受保护关系由既有所有人核定，政策摘要固定；C/D 使用同一执行能力。
- 五项真实变更经原生 writer 和独立 KiCad 验证，精确 delta 相等、protected-diff 为空；负例全部阻断。
- 普通操作 strict 保持；例外无法被提议器自行开启或扩大。
- 固定故障输入快照、单轮快照、写后/重启恢复与字节比较通过。
- source、输出、工具、库、政策与事实的 hash 绑定完整；成功状态没有 NOT_RUN/UNKNOWN/TOOL_ERROR 的必需检查。
- 新增副作用在当前 candidate 内，现有 Sandbox 权限与 promotion 检查未被旁路；U3 背景阻断保持。

**No-Go：**

- 仍只能说“底层会写”，缺独立重验；或只看 exit 0/applied/ERC/若干规则。
- 只能靠全局关 strict、改名/删身份、整图重建、手写 KiCad 文本或任意 shell。
- 例外依据是模型声明，或只允许“USB 网络附近任意变化”“最多两个 split”。
- 任何 protected 回归、旁路残留、证据不新鲜、输入/政策漂移、失败无法还原或权限缺失。

预期 strict 拒绝是 BLOCKED，不是 TOOL_ERROR；工具崩溃/格式不合法/恢复失败是 TOOL_ERROR；拓扑或关键事实无法确定是 UNKNOWN。后三者都不能执行/接受候选，不能把它们算成 C/D 决策修复失败来证明 AI 无增益。

P3 当前仍有 F-U1-03、F-U1-04、F-U1-05b 三项待人工核验；Y1 范围也仍有待复核事项。局部批准基线恢复、工具资格和原厂建议的 B 评分是不同问题，不能用本报告自动清掉这些状态。[P3 核验状态](https://github.com/Yenefa/AEDL/blob/8f4d904f2e023c232461aaf65f21e5df9dc7063b/notes/device-facts/m2-device-facts-v1.md#L229)。

## 11. 最后裁决：继续作为核心，还是降为参数编辑适配器

**现有证据不支持立即把 akcli 降为纯参数工具。** 原生 writer 已在 M2 副本完成 DC-01/DC-03，具备保留为原生编辑后端的理由；需要补的是 AEDL 授权差分、独立验证和事务接受边界。可信 Repair Executor 的核心应是这套 AEDL 确定性执行链，akcli 承担受控写入角色。

**如果 DC-01 和 DC-03 在上述约束下仍不能通过独立资格验收，就应降级，不能继续宣称它是完整 Repair Executor 核心。** 可保留已验收的参数编辑，以及 DC-04/05 等已证实安全的原语子集；拓扑修复能力继续 BLOCKED，另行评估现有编辑接口。不能为维持 akcli 的核心定位牺牲 fail-closed 或 Sandbox 边界，也不应继续开展依赖该能力的 Y4 修复率比较。
