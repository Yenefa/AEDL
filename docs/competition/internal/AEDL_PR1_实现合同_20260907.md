## 4. 数据接口：Proposal 与 HostPatch 分开

所有对象拒绝未知字段；JSON 拒绝重复 key、NaN/Infinity、超限深度、歧义 ID。限制：UTF-8 请求 ≤64 KiB、深度 ≤12、op 数 1–8、诊断 ≤16 条、每条文字 ≤2048 字符。hash 为小写 64 位 hex。标识为 1–64 位 ASCII 字母/数字/`_`/`-`。集合列表不得重复；整数不能接收 bool。

**公开输入 PublicContext**：`schema_version=1, context_id, target, base_source_sha256, current_observation, public_facts, generic_op_schema, limits`。host 生成一次并保存其 digest；当前观察可以含当前图、当前对象 UUID 和当前位置。它不包含 host policy 的 `after` 或规则匹配结果。

**Proposal 的 PATCH 分支**，所有列出的字段必填：

```text
{
  schema_version: 1,
  context_id: Id,                         // 回显宿主上下文
  target: CandidateRelativePath,          // 必须等于 PublicContext.target
  base_source_sha256: SHA256,             // 乐观并发条件，宿主重算
  decision: "PATCH",
  oplist: {protocol_version: 2, target_format: "kicad", ops: [Operation]},
  diagnosis: [{rule_id: string, observed: string, fact_ids: [string],
               requirement_level: "MANDATORY"|"RECOMMENDED"|"MARGIN"|"UNKNOWN",
               rationale: string}]
}
```

`diagnosis.rule_id` 是诊断标签，不能映射成执行授权。diagnosis 不影响 route、delta 或 candidate commit；B 维定性评分留后续。错误事实不能由“模型解释得很好”覆盖。

**REFUSE 分支**：同样必填 `schema_version/context_id/target/base_source_sha256` 与 `decision="REFUSE"`，保留 diagnosis，增加 `refusal={reason_code:string, missing_fact_ids:[string], explanation:string, required_human_decision:string}`；**oplist 必须不存在**。合法拒绝终止于 PRECHECK，native 工具调用数为 0、设计写入数为 0。拒绝是否符合 DC-06 的 B 评分不在 PR-1 计算。

**Operation v1** 只开放足以完成已裁决五例的三种原语，不开放任意原生 op：

| op | 必填字段 | 允许的可选字段与限制 |
|---|---|---|
| `delete_object` | `op, uuid` | 无；禁止 match/cascade；uuid 必须命中 policy 绑定的一个 label 或 wire |
| `add_net_label` | `op, name, at` | `scope` 仅 `local`；`rotation` **若提供仅 0**，省略则**保留省略状态**（表示 native pin-derived orientation）；at 仅 `REF.PIN`，不能是坐标/表达式 |
| `place_component` | `op, lib_id, designator, x_mil, y_mil, value, footprint` | `rotation` 仅 0，`mirror` 仅 `none`，`unit` 仅 1；坐标为整数 mil 且与宿主有限许可相等 |

lib_id 公开通用子集为 `Device:R`/`Device:C`，不接受 symbol_source、额外库路径、sheets/group、instance_designators、任意 shell/Python、全局 rename、from-intent/arrange、参数任意覆盖。缺省参数的规范化按字段是否具有执行语义分两类：`add_net_label.scope` 与 `place_component` 的 `rotation/mirror/unit` 是 presence 中性的，缺省时按上述值归一后计算 Proposal digest，不把默认值作为扩权口；`add_net_label.rotation` 的**存在性**是执行语义（pinned writer 以 `"rotation" in op` 选择角度分支），故省略即保留省略、显式 0 即保留 0，二者 canonical Proposal identity 不同，不得互相归一。

`name/designator/value/footprint` 先按无控制字符的有界字符串校验，再由绑定 policy 精确核对。public schema 不写 `R7=22R` 等逐例答案。一个完整 op-list 只能执行一次；E1 必须先删旧标签再添新标签，E3 先删准确旁路再放组件，DC-04/05 必须先 place 再 add labels。相互独立的同阶段操作顺序可以不同，但 digest 保留实际顺序。

**HostPatch** 完全由 pipeline 构造，不能从 Proposal JSON 合并字段：

```text
HostPatch = {
  schema_version: 1, run_id, candidate_id, round_id, patch_id, context_id,
  proposal, proposal_sha256,
  target, base: {files: FileManifest, topology_sha256},
  policy: {id, file_sha256, bound_rule_id, bound_policy_sha256},
  authority: {context_digest, resolved_authorization_refs, decisions},
  toolchain_manifest, toolchain_sha256,
  route: "STRICT"|"CONSTRAINED_EXCEPTION",
  bound_policy, patch_sha256
}
```

这里 `round_id` 是宿主非负整数；policy、facts、源文件、工具的所有摘要均由宿主实际重算。`patch_sha256` 对自身字段以外的完整 HostPatch 计算。快照、stage/report 路径由事务创建函数从 candidate 和 txn_id 派生，**不属于可从模型接收的字段**。

`applied/verdict/verification_pass/accepted/signed_by/snapshot_path/authorization_ref/policy_ref/exception_id/expected_delta` 只要出现在 Proposal 中，一律拒绝。AI 不能自证执行效果，也不能提交一份自写 expected topology 让 verifier 比较。

## 5. hash、图身份与 exact/protected 的精确定义

**文件 hash**：`SHA256(path.read_bytes())`，不解码/重新编码、不换行转换。不拿 Git blob SHA1 或文本 hash 代替原始文件 SHA256。

**canonical JSON**：UTF-8，key 按字典序，紧凑分隔符，无 ASCII 转义、无浮点/NaN；集合先按其稳定 identity 排序，op-list 等有序列表保留顺序。长度/坐标用整数，坐标精确转换为 nm（1 mil=25400 nm）；无法无损解释的值拒绝。摘要为 `SHA256(UTF8("AEDL-PR1:" + kind + ":1\0") + canonical_json_bytes)`，kind 固定为 `manifest/proposal/patch/policy-bound/topology/delta/protected/toolchain/context/receipt` 之一。

`FileManifest={version:1, files:[{path,sha256,size_bytes,role}]}`。path 为 candidate-relative POSIX 路径；排序并拒绝大小写碰撞、ADS、盘符、UNC、`..`、空段、末尾点/空格、设备名。role=`TARGET` 或 `READONLY_DEPENDENCY`。TARGET 恰好一个；所有 design 文件必须被枚举，不接受“只列 .sch”。固件、PCB、intent、BOM、项目、符号库/配置、事实/政策文件都列为只读依赖或 toolchain/facts 的外部只读 manifest。

报告/原生输出清单使用相同 `version/files/path/sha256/size_bytes` 结构，但 role=`REPORT` 或 `NATIVE_ARTIFACT`，不要求存在 TARGET。外部只读依赖清单的 path 是宿主分配的稳定 dependency ID；其绝对路径单独存宿主 binding，不能与 candidate-relative path 混用。toolchain 固定形状：`{version:1, akcli:{version,sdist_sha256,package_files_sha256}, python:{version,executable_sha256}, kicad:{version,executable_sha256}, libraries:FileManifest, configs:FileManifest, execution:{worker_timeout_seconds,kicad_timeout_seconds,argv_profile:"PR1_V1"}}`；其中 libraries/configs 的 role 全为 READONLY_DEPENDENCY，允许空 configs 但必须明确序列化。可执行绝对路径在 host_context，命令版本与实际文件必须匹配 manifest；移动安装位置不等于更换其 bytes。

**TopologyObservation** 必须覆盖整份受支持的 flat M2：

```text
{
  version:1, source_sha256,
  components:[{identity, reference, lib_id, lib_definition_sha256,
               value, footprint, unit, position_nm, rotation, mirror,
               dnp, in_bom, on_board, pin_definition_sha256}],
  pins:[{identity, name, electrical_type, no_connect, partition_key}],
  partitions:[{key, members:[PinIdentity], names:[ScopedName]}],
  source_objects:[{identity, kind, semantic_ast_sha256, descriptor}],
  coverage:{expected_pin_keys_sha256, observed_pin_keys_sha256,
            expected_component_keys_sha256, observed_component_keys_sha256,
            expected_pin_count, observed_pin_count, complete}
}
```

既有 PinIdentity 绑定 sheet instance UUID path、组件 UUID、ref、unit、pin number、pin UUID，不能仅比较显示名。原始 source pin inventory 与 fresh XML coverage 都完整且一一对应才可 PASS。出现漏 pin、重复 ref/UUID、未知 sheet、无法解析的必要字段 → UNKNOWN。net code 和自动 `unconnected-*` 名称不是稳定身份；每个单点未连接 pin 保持独立分区，NC 是独立状态，不把所有 null 合成一个网。元件本体不当导线：R7.1 与 R7.2 必须可以属于不同导电分区。

分区 key 是按完整 pin identities 排序后的集合摘要。命名网络的名称带 scope；M2 根局部标签统一为 `/NAME`。合网前后可能有多个 source label 别名，必须保留集合。KiCad XML 只给 canonical 名时，使用独立只读 source 解析的标签、位置及 XML pin 分区补齐本合同的 pin-anchored labels/已声明直线旁路；不得伪造 XML 带有 aliases。无法唯一归属的 source label/其他几何形态 → UNKNOWN。原始名称保留在私有观察中，跨 parser 比较只采用此已定义投影。

source_objects 由独立只读 S-expression 提取，覆盖所有顶层/嵌套对象；忽略排版空白与数值等价格式，保留字符串内容、数值、子结构顺序及未知节点。禁止用删除大块文本后的粗略 hash 判断保护成功。新增组件整棵 instance 子树允许由固定 native writer 生成，但必须匹配 policy 的所有属性、固定库定义、两根 pin 的身份/位置和无附加电气结构；未知电气字段不能忽略。已有 lib_symbols、symbol/pin 定义、组件属性或未授权对象任何结构变化都算 protected-diff。

**绑定算法**：宿主从当前故障输入解析 before；规则在已获准 rule ID 集合内唯一匹配。pin alias 解析成完整身份；对象选择器必须恰好命中一次，并固定 UUID/type/原 descriptor/hash。capture 的 GND/+3V3 是完整 before 集合，只捕获一次。新组件用 `new:R7` 等唯一角色和 pin number 描述许可；stage 返回的 fresh UUID 仅用于把实际新对象映射到该角色，不能改变许可。既有 UUID 不允许替换；新 UUID 不得与任何既有对象碰撞，数量和引用必须一致。

把受许可的分区替换与组件/对象变化作用于完整 before，生成 HostExpectedAfter；其余全部复制 before。这是 host 的授权关系计算，不是从 golden/acceptance/提议结果学习答案。

`BoundPolicy={version:1, rule_id, route, policy_file_sha256, authority_context_digest, before_source_sha256, before_topology_sha256, pin_identity_map, object_identity_map, captured_partitions, new_component_roles, expected_after, authorized_delta, authorized_delta_sha256, protected_projection_sha256, operation_constraints}`。object_identity_map 存 selector slot→UUID/kind/descriptor hash；captured_partitions 存 slot→完整 members/names；operation_constraints 存数量、准确删除对象、新增 label/组件属性及阶段顺序。使用数据快照而非可再读取/修改的 lazy binding。

`TopologyObservation.source_sha256/coverage` 是 provenance 元数据，不参与 electrical/source-object delta；expected_after 不声称预知 writer 将产生的 bytes hash。bytes 绑定单独由真正的 stage 写入与 export proof 完成。

`actual_delta = diff(before, actual_after)`；`authorized_delta = diff(before, HostExpectedAfter)`。diff 使用明确的 `partitions_removed/partitions_added/components_added/components_removed/component_field_changes/object_changes/no_connect_changes` 集合。比较要求集合/描述符**相等**；不能比较 subset、只比数量、只看 named split/merge、只看 CLI 摘要行。new UUID 在授权对比时按上述唯一角色对齐，字节/source hash 仍绑定实际 UUID。

`protected_diff` 再独立计算：删除且仅删除 policy 明确许可的 changed slots 后，完整 before/after source 与关系投影相等；全部只读依赖的原始 bytes 和文件集合相等。这样同时阻止额外修改和漏修。`unexpected_delta=[]`、`missing_delta=[]`、`protected_diff=[]` 三者均必需。E3 的四个最终分区互不相交，旁路保留必失败，不能用旧五条语义规则代替这些检查。[现有局部语义解析器](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/gates/schematic_semantics.py#L324)

## 6. topology policy 与三层可见性

随附 `topology_policy_v1.draft.json` 是合法 JSON 的 **unbound 数据草案**，此次仅存 outputs，不写仓库。它不是已经批准或可以直接启用的运行许可。其 required_runtime_values 是必填运行输入，按固定绑定算法求值，不能留模板字符串，也不能靠手填常量假装已批准。

`enabled_by_default=false` 在静态文件中保持不变；effective enabled 仅在宿主解析到真实批准记录、该记录绑定当前 policy digest/rule/run/candidate/操作范围、且现有动作权限全部 ALLOW 时为 true。`approved_rule_ids` 必须从该解析结果派生，不接收一个用户JSON数组作为授权。没有批准记录时五条规则都不能执行；测试可显式注入标记为 TEST_ONLY 的授权假件验证控制流。

| 层级 | 可读者 | 允许内容 | 禁止跨出的内容 |
|---|---|---|---|
| proposer/public | C、D 相同输入接口 | 当前故障图/对象、冻结公共事实及其真实核验状态、通用 op schema、候选相对 target、当前源 hash、预算 | per-case rule、授权后的操作清单、expected after/delta、标准答案 |
| host-only | pipeline、adapter 的最小调用投影、thin verifier | 五条规则、精确许可、before bindings、受保护投影、policy/工具/事实 hash、既有批准引用、快照/内部报告 | 以上任何 expected/member/坐标/策略提示不得进入 C/D prompt 或反馈 |
| acceptance/private | 独立验收测试/后续评分者 | 从 P4 独立核定的 expected topology、负例期望、标准补丁（若保留）、B rubric、评分 | 不供 proposer、runtime policy binder、adapter 或 runtime verifier 作为答案来源 |

`src/repair/topology_policy_v1.json` 的仓库位置不意味着它是 proposer 可读资产。C/D 只得到显式白名单序列化的 PublicContext；不能把整个仓库、tests、policy 文件或本合同挂给 C/D。实现 Agent 需要读取本合同与 host policy；**同一个已读答案的会话不能冒充未曝光的 C/D 计分会话**。曝光登记沿用 PR-3 既有实验准备，不在 PR-1 建新隔离系统。

公开反馈固定形状：`{context_id, proposal_outcome, reason_code, observed_issue_ids}`。proposal_outcome=`APPLIED_TO_CANDIDATE/NO_CHANGE/REFUSED/REJECTED/EXECUTION_UNAVAILABLE`；reason_code 仅公开粗粒度 `OK/PROPOSAL_INVALID/REPAIR_NOT_AUTHORIZED/REPAIR_CONSTRAINT_VIOLATION/INPUT_CHANGED/EXECUTION_UNAVAILABLE`。COMMITTED/NO_CHANGE/REFUSED 分别映射前三项；BLOCKED 或 ROLLBACK(cause=BLOCKED) 映射 REJECTED；TOOL_ERROR/UNKNOWN 及相应 cause 的 ROLLBACK 映射 EXECUTION_UNAVAILABLE。observed_issue_ids 只可引用本来已公开的发现 ID。不返回 host rule ID、route、expected/actual diff 详情、差几条即可通过、标准 patch、内部报告路径、raw stdout/stderr 或细粒度 policy exception。

必须实现 `make_public_context(...)` 与 `public_feedback(receipt)` 的白名单构造并测泄漏；禁止把私有对象复制后删几个字段。C/D 的当前问题观察可以帮助修复；宿主 policy 的标准终态不能借“约束提示”之名发给 C/D。

## 8. 模块调用接口与回执

以下是待实现 API 合同，不声称 master 已有这些函数。接口数据可使用普通 dict/不可变 dataclass；不新增 shared protocol 文件。返回值序列化形状必须与此一致。

```text
tools.repair_pipeline:
  parse_proposal(raw_utf8: bytes) -> Proposal
  bind_policy(host_context, proposal, native_before) -> BoundPolicyResult
  run_round(host_context, proposal_utf8: bytes) -> TransactionReceipt
  recover_incomplete(host_context) -> RecoveryResult
  make_public_context(host_context, current_observation, public_facts) -> PublicContext
  public_feedback(receipt: TransactionReceipt) -> PublicFeedback

tools.akcli_adapter:
  read_native(read_request) -> NativeReadResult
  apply_stage(stage_request) -> StageApplyResult
  worker_main() -> exit_code       // 固定 READ / APPLY_EXCEPTION，非任意任务执行器

gates.repair_verification:
  hash_bytes(raw: bytes) -> SHA256
  canonical_sha256(kind, json_value) -> SHA256
  compare_delta(before, after, bound_policy) -> DeltaCheck
  compare_protected(before, after, bound_policy, dependency_manifests) -> ProtectedCheck
  verify_stage(verification_request) -> ThinVerificationResult
```

`host_context` 只能由宿主调用方构造：run/candidate/round/patch/context IDs、CandidateWorkspace、固定 target、初始 context digest、只读文件与 toolchain manifest、静态政策路径、既有身份/grants/批准记录解析器、原生执行路径、超时限制。它不是一个从 Proposal 反序列化的对象。原生 worker timeout≤60s、每次 KiCad export timeout≤60s，值由 host 在 PublicContext limits 中冻结；单轮无自动重试。

`BoundPolicyResult={status:PASS|BLOCKED|TOOL_ERROR|UNKNOWN, bound_policy|null, host_patch|null, reasons:[Finding]}`。没有真实批准依据或现有 `PolicyPort.evaluate` 对实际 TOOL_EXECUTE/FILE_WRITE 任一不为 ALLOW，则 BLOCKED。授权上下文从既有宿主 state/ledger 解析，不能从模型 subject 的 boolean 提取。standalone 测试可注入假件，生产没有默认 allow。批准必须绑定此 policy digest、rule、run/candidate 和实际 tool/写路径；这只是对既有权限的消费，不创建新 grant/signature 类型。

`read_request={host_binding, absolute_read_root, relative_target}`；`NativeReadResult={status, source_sha256, observation|null, raw_artifact_hashes, reasons}`。adapter 使用固定 0.21.0 的 `akcli.readers.kicad.read_sch` 等已知入口收集完整分区和 source 描述，不能只返回 `net_diff.lines`。

NativeReadResult.status 为 PASS/BLOCKED/TOOL_ERROR/UNKNOWN，并额外返回 `connectivity_findings`（与 StageApplyResult 相同结构），供 before/after warning 集合比较。host_binding 至少含 run/candidate/txn、toolchain digest、只读路径授权上下文；不能是可由 proposer 指定的 route 字段。

`stage_request={host_patch, txn_id, stage_root, stage_target, oplist_path, native_artifact_root}`；上述路径均由 pipeline 推导且重新验证。adapter 不接受可由 JSON 单独伪造的 `authorized=true`，调用入口必须有经宿主解析的执行上下文。

```text
StageApplyResult = {
  status: "APPLIED_TO_STAGE"|"BLOCKED"|"TOOL_ERROR"|"UNKNOWN",
  txn_id, patch_sha256, bound_policy_sha256, route,
  tool: {mode:"CLI"|"PYTHON_WRITER", version, artifact_sha256,
         exit_code:integer|null, tool_applied:boolean|null,
         op_results:[{op_index,op,status,created_uuids,error_code,message}],
         connectivity_findings:[{code,severity,message}]},
  before_source_sha256, after_source_sha256, changed:boolean,
  native_before, native_after, raw_artifacts:FileManifest, reasons:[Finding]
}
```

strict 精确命令（argv 数组、shell=false）：`akcli draw <stage.sch> --ops <host-oplist.json> --apply --strict-nets --no-erc --json`。`--no-erc` 只停用 upstream 的 advisory ERC；保留 strict 与 writer connectivity，正式 ERC 仍归 PR-2。不得加 `--flat/--no-net-diff/--allow-open`。flat M2 前置必须已经证实，无层级才允许此 PR-1。

exception 在固定 Python worker 内只调用 `akcli.writers.kicad.apply(oplist, stage_path, apply=True, sources=None, backup_dir=host_dir, backup_depth=1, tol_nm=0, verify_out=findings, allow_open=False)`。保留原生 envelope、GUI 锁、逐 op 错误、connectivity、重新解析和 atomic writer，不 monkeypatch。API 原生没有 applied 字段，回执 `tool_applied=null`；不能伪造 true。[固定 writer API](https://github.com/tipoLi5890/akcli/blob/68c2df5e43db2f822ab8dbfea36f777396897d8d/src/akcli/writers/executor.py#L69)

STRICT 只有 exit=0、标准 draw-result、applied=true、op_results 完整且全 ok、源 bytes 改变并成功重读时才返回 APPLIED_TO_STAGE。dry-run exit=0/applied=false 不通过；首次 no-op 不通过。exit=6 的合法拒绝错误对象可没有 applied，识别为 BLOCKED，不伪报 malformed。其他不完整/矛盾回执、原生错误、工具缺失/超时 → TOOL_ERROR。exception 同样要求每个 op ok、真实字节改变及重读成功；不能用 API list 非空作为成功条件。

任何 ERROR/CRITICAL connectivity finding 阻断；WARNING 必须与 before 的同码/同对象 finding 集合比较，新 warning 和任何 NO_CONNECT_CONFLICT 阻断。已有原生 warning 仅在 host 明确冻结为 background 时保留。未知 severity/无法比较 → UNKNOWN。这是写入完整性检查，不扩展 ERC 规则。

route 在 PRECHECK 冻结：只有五条中唯一匹配且已获准的规则可以执行。E1/E2/E3 **直接**进入 exception；DC-04/05 **直接**进入 strict。不得先试 strict 被拒后自动升级，也不得把任何 exit=6 翻译成成功。

`Finding={code:string, stage:Phase, object_id:string|null, detail:string}` 为 host-only。至少固定 reason codes：`REPAIR_SCHEMA_INVALID / REPAIR_AUTH_DENIED / REPAIR_POLICY_DISABLED / REPAIR_INPUT_DRIFT / REPAIR_SELECTOR_AMBIGUOUS / REPAIR_STRICT_REFUSED / REPAIR_EFFECT_MISMATCH / REPAIR_DELTA_MISMATCH / REPAIR_PROTECTED_DIFF / REPAIR_TOOL_UNAVAILABLE / REPAIR_TOOL_PROTOCOL_ERROR / REPAIR_TIMEOUT / REPAIR_EXPORT_STALE / REPAIR_SOURCE_UNBOUND / REPAIR_COVERAGE_INCOMPLETE / REPAIR_PARSER_DISAGREEMENT / REPAIR_ROLLBACK_FAILED / REPAIR_RECOVERY_AMBIGUOUS`。不把这些写入 Sandbox 的新 enum。

StageApplyResult 的 op_results 必须逐一覆盖 0..n-1，status 仅 `ok/error`；native reported created UUIDs 必须与实际新增的对应顶层对象一致；未被 API 单独列出的 symbol 子 pin UUID 由 source inventory 检查 fresh/unique/parent/pin-number，不伪造 API 返回它们。connectivity severity 规范化为 `INFO/WARNING/ERROR/CRITICAL` 并保留原始回执。未知值不降为 INFO。DeltaCheck 与 ProtectedCheck 的闭合返回结构如下：

```text
DeltaCheck={status:PASS|FAIL|UNKNOWN, authorized_delta_sha256:SHA256|null,
            actual_delta_sha256:SHA256|null, missing:[], unexpected:[],
            coverage_complete:boolean, reasons:[Finding]}
ProtectedCheck={status:PASS|FAIL|UNKNOWN, before_projection_sha256:SHA256|null,
                after_projection_sha256:SHA256|null, changes:[],
                dependencies_unchanged:boolean, reasons:[Finding]}

```

所有 diff item 为 `{section,identity,field,before,after}`，before/after 为规范 JSON 值，缺失用结构化 `{absent:true}`，不用空串/null混淆。delta/protected 纯函数不执行工具，读取失败由调用方分类；数据本身不完整返回 UNKNOWN，完整数据违反条件返回 FAIL。

## 9. thin verifier 的精确输入、输出与 commit 条件

```text
VerificationRequest = {
  txn_id, run_id, candidate_id, patch_sha256, bound_policy_sha256,
  snapshot_root, stage_root, relative_target,
  before_manifest, staged_manifest, bound_policy, toolchain_manifest,
  native_before, native_after, report_root
}
```

root/manifest/policy 来自 pipeline 的宿主对象；native observations 只作相互校验，不能代替 KiCad observation。verifier 首先重算 snapshot、stage 和依赖 hash，输入不匹配便返回非 PASS。

KICAD_VERIFY 内对 **snapshot before 和 stage after 各执行一次新的导出**：

```text
kicad-cli sch export netlist --format kicadxml --output <new-dir>/before.net.xml <snapshot.sch>
kicad-cli sch export netlist --format kicadxml --output <new-dir>/after.net.xml <stage.sch>
```

固定 KiCad **10.0.5** 与宿主配置的符号环境；toolchain manifest 包含 akcli 发行包/Python runtime/KiCad binary/version、library/config 文件摘要及固定命令参数。缺值/版本不同不得静默继续。使用 shell=false，输出目录为本次唯一新目录，启动前不存在输出文件；不按 mtime 单独认定新鲜。不调用 `gates/run_gates.py --skip-kicad` 或历史 netlist fallback。

两次进程都必须正常完成、exit=0、产出非空且可解析的本轮 XML；记录 source 在导出前后及解析结束后的 SHA256、输出 bytes hash、argv、工具 fingerprint、txn ID。三个 source hash 均必须等于请求对应 source。报告中“源路径相同”不能代替该证据链。依赖集合/内容在验证开始结束也必须一致。

verifier 独立构造 before/after 的完整 KiCad 分区及 source AST 保护观察；对 both before and after 的可比较完整分区、组件/pin 身份与 native 观察做一致性检查。初始 native 错读而误授权的 stage 也必须在这里被拒绝。导出成功而 pin/属性 coverage 不完整为 UNKNOWN；不是 PASS。稳定、完整但存在真实额外/缺失变化为 FAIL；source drift 或缺授权为 BLOCKED；命令/输出协议故障为 TOOL_ERROR。

```text
ThinVerificationResult = {
  schema_version: 1, scope: "PR1_CANDIDATE_BYTES",
  status: "PASS"|"FAIL"|"BLOCKED"|"TOOL_ERROR"|"UNKNOWN",
  txn_id, run_id, candidate_id, patch_sha256, bound_policy_sha256,
  before_source_sha256, staged_source_sha256, toolchain_sha256,
  checks: {
    fresh_export: Check,
    source_hash_binding: Check,
    exact_topology_delta: Check,
    protected_diff: Check
  },
  coverage: {before: Coverage, after: Coverage},
  parser_agreement: {before: Check, after: Check},
  authorized_delta_sha256, actual_delta_sha256,
  unexpected_delta: [], missing_delta: [], protected_changes: [],
  dependencies_unchanged: boolean,
  exports: [ExportProof], reports: FileManifest,
  deferred: {erc:"NOT_RUN", semantic_runner:"NOT_RUN", formal_evidence:"NOT_RUN"},
  reasons:[Finding]
}
Check = {status:"PASS"|"FAIL"|"BLOCKED"|"TOOL_ERROR"|"UNKNOWN"|"NOT_RUN",
         reason_codes:[string], artifact_paths:[host_relative_path]}
ExportProof = {role:"BEFORE"|"AFTER", txn_id, argv, exit_code,
               source_before_sha256, source_after_sha256, source_parse_end_sha256,
               xml_path, xml_sha256, toolchain_sha256, completed:boolean}
```

PASS 时四个 required checks **全部 PASS**，两份 Coverage.complete=true 且 expected/observed keysets 相等，parser_agreement 两项 PASS，exports 恰好 BEFORE/AFTER 两项且证明有效，delta hashes 相等，三个 diff 列表为空，dependencies_unchanged=true。非 PASS 允许部分 observation/proof 不存在或 hash=null，但必须保留已完成检查，未做项为 NOT_RUN；空列表本身不等于通过。

**pipeline 唯一 commit 谓词**：

```text
StageApplyResult.status == APPLIED_TO_STAGE
AND route/tool-result/one-write-call/effect checks 全部成立
AND ThinVerificationResult.scope == PR1_CANDIDATE_BYTES
AND ThinVerificationResult 满足上段所有 PASS 不变量
AND txn/run/candidate/patch/policy/toolchain bindings 完全相等
AND verifier 返回后重算 stage source/report hashes 与回执一致
AND live design 仍等于 round snapshot 的整个 manifest
AND 当前政策/执行权限仍允许本次 commit，policy/facts/dependencies 无漂移
AND 单写者锁仍由本事务持有
```

这是合取，没有“置信度高”“仅 warning”“多数 checks PASS”的例外。正式 `VerifierPort` 的 VerificationStatus 不增加 TOOL_ERROR/UNKNOWN；PR-1 使用上面的局部结果类型，**不把 thin PASS 发布为整候选正式 VerifierPort PASS**。正式 Sandbox 接入、ERC/semantic/evidence runner 与其状态映射由 PR-2 完成；如走已有正式流程，其现有门禁继续生效。

thin verifier 的非范围项：ERC 调用/分级、跨 intent/PCB/firmware 重新语义推理、五条语义 runner 整合、DRC、整板/U3 通过判定、Evidence manifest 发布、B 评分。E2 的 0x44 前置来自已冻结只读事实，并核对实际固件常量/bytes，属于本条政策的必要前置，不扩展为通用 firmware semantic runner。

## 10. 单轮状态机与 fail-closed 条件

Phase 固定：`PRECHECK → SNAPSHOT → STAGE_APPLY → DELTA_CHECK → KICAD_VERIFY → COMMIT`。任何失败转入 `ROLLBACK / BLOCKED / TOOL_ERROR / UNKNOWN` 的终止处理，**同一轮不重提、不重试、不降级验证**。

为避免把“恢复成功”误读为“修复成功”，固定两个字段：

```text
TransactionStatus = COMMITTED | NO_CHANGE | REFUSED | ROLLBACK | BLOCKED | TOOL_ERROR | UNKNOWN
cause_status       = null | BLOCKED | TOOL_ERROR | UNKNOWN
RollbackStatus    = NOT_NEEDED | VERIFIED | FAILED | UNKNOWN
```

verifier FAIL 映射 `cause_status=BLOCKED`，保留原 verifier.status=FAIL 与 finding；不丢失设计失败和工具故障的区别。`NO_CHANGE` 只用于已验证 COMMITTED 回执的幂等重放，不能用于首次空修复。REFUSED 只用于合法 REFUSE proposal。

| 步骤 | 必须执行 | fail-closed 条件及去向 |
|---|---|---|
| PRECHECK | 获取 candidate 单写者锁；先处理未完成事务；校验 Proposal/context/path/file manifest/toolchain；native before 全量读取；policy 唯一绑定；验证既有 TOOL_EXECUTE/FILE_WRITE 及实际路径授权 | 坏输入、缺批准、rule 不匹配/多匹配、链接/GUI 锁/并发、hash 漂移 → BLOCKED；工具错误 → TOOL_ERROR；无法确定身份/coverage → UNKNOWN。设计未写，不新建覆盖式快照。合法 REFUSE 直接 REFUSED。 |
| SNAPSHOT | 首次轨迹保存 immutable 故障输入快照；本轮保存 immutable 写前快照；journal 写入并 flush/fsync 后复制；校验完整文件集合及 bytes；创建独立 stage | 已存在同 ID 不同内容、copy/hash/落盘失败、snapshot 可被 stage 访问写入、输入过程中变化 → 不进 STAGE；可证明无设计变更则 TOOL_ERROR/BLOCKED，不能证明则 UNKNOWN。 |
| STAGE_APPLY | 复制 snapshot 的 design/context；仅 stage target 可改；native 只调用一次；采集真实结果、前后 bytes、完整重读及 sidecar 清单 | strict 拒绝、op 错误、applied 矛盾、首次不改 bytes、重读失败、任何未授权 source/依赖变化、新 NC 冲突 → ROLLBACK 终止处理；保存原因。不得改走 exception 或跑第二次部分补丁。 |
| DELTA_CHECK | 用 native 完整前后观察做 exact/protected 初检；核对 native 输出对象与实际新 UUID；检查 source AST 及文件集合 | unexpected/missing delta、保护投影不等、错误属性/别名/NC/额外对象 → ROLLBACK(cause=BLOCKED)；解析分歧/不确定性 → ROLLBACK(cause=UNKNOWN)。该步通过仍不允许 commit。 |
| KICAD_VERIFY | 执行第9节两次 fresh 导出及四项检查，冻结所有报告和 staged manifest | 缺工具/超时/坏 XML → ROLLBACK(cause=TOOL_ERROR)；旧报告/源漂移/真实回归 → ROLLBACK(cause=BLOCKED)；coverage/必需属性缺失/解析器分歧 → ROLLBACK(cause=UNKNOWN)。 |
| COMMIT | 再次检查 commit 谓词；先持久化 COMMIT_INTENT 与 verified staged hash；从 stage 读取固定 bytes，hash 对齐；同一 design 目录写临时文件、flush/fsync、原子 replace；逐字节和 hash 核验最终 design | 权限/输入/stage/report 漂移 → 不 replace 并 ROLLBACK；replace/post-read/journal 错误 → 依恢复规则处理。禁止为了提交重跑 op-list。只有已验证 bytes、最终核验与 terminal journal 均完成才 COMMITTED。 |

运行目录：`candidate/design/...` 为候选设计；`candidate/.repair/<txn_id>/{snapshot,stage,reports,native-artifacts}/` 为 host-controlled 事务区；`candidate/.repair.lock` 为内容固定、不因 unlock 删除的锁文件。op-list 只指向 stage target，不允许目录路由。snapshot 不可覆写；stage 不得为 symlink/hardlink 副本；候选内到兄弟 candidate 的链接同样拒绝。

在 candidate root 上重新执行 `policy.paths.resolve_within(..., strict=True)`，再检查每个路径分量的 symlink/reparse point、文件 link count/别名与实际身份；不能仅复用 workspace root 的宽范围检查。无法检验的平台返回 UNKNOWN。[既有路径实现](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/sandbox_runtime/src/aedl_sandbox/policy/paths.py)

akcli 日志/备份必须限定于 host 预先解析并冻结的 stage 内 `.akcli`/native-artifacts 路径；工作区发现不能上溯到其他 candidate/仓库。只将固定版本已知的 journal/backup/config 类型列入 sidecar 清单，禁止从实际输出自动扩白名单。未知路径、新的工程文件、隐藏依赖写入均阻断。sidecar 不参与 design manifest，但参与既有 candidate_hash。

**恢复规则**：

1. 从未发布 stage 时，live design 应等于 round snapshot；逐 bytes/manifest 核对后 `rollback.status=VERIFIED`，无需为了“回滚”重写未变文件。
2. 已 replace 或由本事务留下的部分提交：仅当 live target 为已记录的本事务 before/after bytes、其他 design/依赖仍匹配，才用 snapshot 的原 bytes 经 temp→fsync→replace 恢复；不得用正确 golden 图或 akcli undo/.bak。恢复后逐字节与 hash、文件集合均匹配才 VERIFIED。
3. 任意无权限 protected 文件改变，或 live bytes 不是已记录 before/after、快照损坏：隔离现场，不覆盖可能的人类/其他进程修改；恢复操作失败为 TOOL_ERROR，无法判定归属/最终状态为 UNKNOWN；不再开下一轮。
4. 崩溃重启先读 durable journal，不用会跳过坏行的历史 `get_recorded_action` 作为唯一恢复依据。无 COMMITTED terminal record 的事务，即使有 COMMIT_INTENT 且 live=after，也按第2条恢复；不猜测这次已经成功。存在完整 terminal record 时，只有全部源/报告/依赖匹配才重用结果；否则 BLOCKED/UNKNOWN。
5. ROLLBACK 表示失败事务已经恢复/确认原设计，`cause_status` 保留原失败类别；恢复本身失败最终为 TOOL_ERROR/UNKNOWN，不得仍记 ROLLBACK 或成功。PRECHECK 前的无写失败则直接 BLOCKED/TOOL_ERROR/UNKNOWN，rollback=NOT_NEEDED。

事务锁、不可变快照、COMMIT_INTENT、terminal record 都必须在对应副作用前/后按规定持久化。保证范围为进程异常/可检测 I/O 故障与重启恢复；不虚构未验证的突然断电、磁盘物理损坏保证。

**幂等**：键 `(run_id,candidate_id,patch_id)`；重复键不同 proposal/patch/policy/context digest → BLOCKED。相同键只有已有 COMMITTED 回执且当前 design/dependencies/tool/policy/report 仍匹配，才返回 NO_CHANGE、复用 snapshot/回执、不调用工具、不增加修复次数。不满足这些条件的旧失败回执不能转成成功。新一轮必须使用新 patch_id/context 并重新绑定当前输入，轨迹初始快照始终保持故障起点。

**最终回执**：

```text
TransactionReceipt = {
  schema_version:1, run_id,candidate_id,round_id,patch_id,txn_id,
  status:TransactionStatus, last_phase:Phase, cause_status,
  proposal_sha256, patch_sha256, policy_sha256, bound_policy_sha256,
  toolchain_sha256, initial_snapshot_id, round_snapshot_id,
  before_design_manifest, staged_design_manifest|null, final_design_manifest,
  stage_result|null, delta_check|null, thin_verification|null,
  commit:{attempted:boolean, replaced:boolean, verified:boolean},
  rollback:{status:RollbackStatus, attempted:boolean, byte_equal:boolean|null, reasons:[]},
  background_blockers:[{id:"U3",status:"BLOCKED_POWER_THERMAL"}],
  full_verification_status:"NOT_RUN", formal_evidence_status:"NOT_RUN",
  raw_artifacts:FileManifest, reasons:[Finding], replay_of:null|Id
}
```

失败 phase 之前的必需结果 null/NOT_RUN，不填假 PASS。真正发布 candidate bytes 的 COMMITTED 与后续 NO_CHANGE 复用结果必须可区分。

design 恢复成功不要求 candidate 整体 hash 回到旧值：失败 stage/报告仍被保存。最终事务文件全部定稿后再调用现有 `CandidateWorkspace.candidate_hash`；最后的整体 hash 和 receipt digest 写入既有排除的根 `.actions.jsonl`/宿主状态，不能写回参与该 hash 的报告而造成自引用。之后 candidate 任一非排除内容变化均使该整体绑定失效。[既有 hash 规则](https://github.com/Yenefa/AEDL/blob/01e30d6a33ca959d2197736242ee49de5a11f476/sandbox_runtime/src/aedl_sandbox/workspace.py#L158)

## 12. 编码起点与完成边界

实现 Agent 只需按 C1→C6 填入上述函数和数据规则；不得再次研究 akcli 是否可承担五例、修改 upstream 或推导一套新 AEDL 架构。具体实现内部可以选择 dict/dataclass、测试辅助函数组织，不能改变 schema、单写轮次、身份/hash、授权、可见性和 commit 条件。

静态草案的默认 disabled、运行时真实批准记录、工具绝对路径、当前输入 UUID/hash 都是明确的 runtime bindings。没有这些值时按合同拒绝运行；其格式、来源、解析方式和缺失行为已经冻结，不是阻止编码的接口缺口。

完成 PR-1 需要单测与原生完整通道验收通过；本次只验证文档/JSON结构和接口覆盖，没有运行这些尚未实现的测试。`READY_TO_IMPLEMENT` 的含义仅为实现合同闭合，不能写成 `IMPLEMENTED / Y4_READY / MANUFACTURING_READY`。
