## 规则与事务

| policy | route | 必须完成 |
|---|---|---|
| E1/DC-01 | CONSTRAINED_EXCEPTION | U1 两个 USB 端点精确换回，其他关系不动 |
| E2/DC-02 | CONSTRAINED_EXCEPTION | 单点 U2.2 并入 GND，固件 0x44 不动 |
| E3/DC-03 | CONSTRAINED_EXCEPTION | 删除两条精确旁路、恢复 R7/R8 22R；四分区独立、无残余短路 |
| DC-04 | STRICT | 单批放 R9 10k 并接 +3V3/BOOT |
| DC-05 | STRICT | 单批放 C5 1uF 并接 EN/GND |
| DC-06 | 无写入 | REFUSE；U3 背景 BLOCKED 保留 |

route 由 host 预先绑定，不以 strict 失败触发 fallback。DC-04/05 不拆成两个 apply。几何、完整成员集合、对象选择器、组件值/封装/装配状态以随附 JSON 为准；不能把 exact 改成 subset。

状态只走：

```text
PRECHECK → SNAPSHOT → STAGE_APPLY → DELTA_CHECK → KICAD_VERIFY → COMMIT
失败     → ROLLBACK / BLOCKED / TOOL_ERROR / UNKNOWN
```

事务回执终态为 `COMMITTED/NO_CHANGE/REFUSED/ROLLBACK/BLOCKED/TOOL_ERROR/UNKNOWN`；恢复结果和原失败原因分开记录。所有失败停止本轮；恢复失败或状态不明不能继续下一轮。

COMMIT 必须同时满足：stage 实际改变并重读成功；verifier.scope=`PR1_CANDIDATE_BYTES`；fresh_export/source_hash_binding/exact_topology_delta/protected_diff **全部 PASS**；before/after覆盖完整、native与KiCad一致；三个 missing/unexpected/protected差异列表为空；所有 txn/source/policy/tool/report bindings 匹配；live design仍等于本轮snapshot；权限有效且锁仍持有。

提交仅复制已经核验的 stage bytes，经同目录 temp→fsync→replace→逐 bytes/hash 校验。禁止再跑 op-list。恢复仅使用原始故障/本轮写前 bytes；不使用 golden、undo 或滚动 .bak。失败 stage/报告可以保留，design hash 与整体 candidate_hash 的恢复声明必须分开。

## 可见性和最低安全不变量

PublicContext 只含当前观察、已冻结公共事实、通用 op schema、当前 target/hash 与 limits。host policy 的 after、expected delta、精确许可、snapshot/raw reports 不发给 proposer。acceptance/private 只给独立验收者，不能成为 runtime policy binder 或 C/D 的答案来源。

`public_feedback` 使用白名单构造；不给 expected/actual差分、route、E1/E2/E3、标准补丁或内部报告路径。实现 Agent 读到答案是工程需要；该会话不能作为未曝光 C/D 实验会话。

缺实际批准时政策保持禁用；缺 KiCad 10.0.5、固定 akcli 0.21.0/Python 3.11/库摘要时拒绝执行或接受。这些是已经定义的运行前置输入，不能实现成默认 allow，也不需要重新设计授权系统。
