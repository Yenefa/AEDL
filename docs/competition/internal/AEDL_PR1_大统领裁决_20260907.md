## 核心裁决

> **保留 akcli，但重新定义它的身份：它不是 AEDL 的安全 Repair Executor；它是 AEDL Repair
> Executor 下面的受控 KiCad writer。**

真正的 Repair Executor 是：

```text
AEDL policy + candidate transaction + akcli writer
            + exact topology diff + independent KiCad verifier + rollback
```

生产启用状态：**NO-GO**（例外授权、事务恢复、独立 KiCad 重验未闭合）。

## 三条实验结论（答辩级证据）

1. **strict-nets 不是 Repair Policy**——它只是 named-net split/merge 检测器，不知道拓扑差分
   是否被工程要求授权。AEDL 增加 constrained exception 是合理的架构补充，不是绕过安全检查。
2. **DC-03 负例 = "Tool says APPLIED ✅ but Engineering verifier says FAIL ❌"**——只补 R7/R8
   保留旁路时 strict 返回 exit 0 / applied=true，但电阻两端实际短接。这是 AEDL
   Verification-first 定位的真实实验证据。**执行成功不是工程正确性证据**——此句升格为
   AEDL 核心设计原则之一（有实验支撑，非 PPT 哲学）。
3. **事务原子性**：place + connect 必须同一 op-list 一次提交（DC-04/05 分两次第二步被拒）。
   AI 不应输出"round1 放 R9 / round2 连 R9"，而是一次提出语义完整的 repair patch。

## 必须提前防的坑：Y4 答案泄漏

`topology_policy_v1.json` 写 exact before/after topology 在**授权层**合理，但**绝不能把完整
after topology 喂给 C AI 或 D baseline**。必须分离：

- **Proposal-visible policy**（C/D 可见）：允许修复范围（如"U1 USB 差分对 / R7/R8 拓扑 /
  其他电路不许动"）。
- **Host-only acceptance policy**（仅宿主/验收侧）：期望的最终引脚归属（expected final pin
  membership）。

模型只能提出 proposal（"move U1.13 to USB_DM"），宿主拿 proposal 对照 host-only policy；
模型不能读取正确答案。与 Percy 独立验收原则一致。

## PR-1 / PR-2 边界修订（强制）

原计划"PR-1 write / PR-2 verify"不成立：对 constrained exception，**没有 independent
verification 就绝不能允许 writer 结果 commit 到 candidate**。修订为：

- **PR-1 = Minimum Safe Repair Transaction**：patch schema + topology policy + akcli adapter
  （strict CLI / 受限原生 writer 双分支）+ snapshot/stage/recovery 事务 + **最薄验证前移**
  （fresh KiCad export + exact topology delta + protected diff）。不前移则例外保持禁用。
- **PR-2 扩展**：full repair verification + ERC freshness + semantic rules + evidence manifest
  + runner 集成。
