## 2. 三项反馈的裁定

### 第一项：增加 B 定性记分，成立

P4 §3.1 已实际写入 A/B 两维。旧 Y4 虽有“解释可核验性”诊断项，但未明确列出要求等级的独立结果，确实可能让“恢复正确、定性错误”被笼统包装成成功。

修订后：

- A 保留原来的稳定修复 `n/5`，修复轮数、重复次数及投入门槛不变。
- 结果表新增一列 `定性正确/3（B；分别记 D/C）`，同一单元格分别记两个组，不混成一个分数。
- B 稳定正确案例数为 `n/6`；DC-06 的 A 是 `NOT_APPLICABLE`。
- 明确“A 通过、B 失败”与“A 失败、B 通过”都可能发生，互不补偿。
- “批准基线恢复检查 FAIL”不等于“违反厂家强制条款”。B 核查完整定性和依据，不按 FAIL 一个词判错。

原件支持：p12 GPIO9 默认弱上拉；p22 内部上下拉为 45kΩ 典型值，表格条件为 3.3V、25°C；p34 EN RC 使用建议措辞。冻结指南也明确推荐 GPIO9 外部上拉，故它并非没有原厂依据，只是不能升级为强制条款。默认电平还需保留外部未强制拉低等适用条件。

### 第二项：P3/P4 已存在，成立；“全部可以直接跑”则不成立

已移除“尚未找到、需 Percy 重新交付”的当前状态表述，改为引用上述 PR 的精确提交，不等合并、不重新制定事实目录和案例定义。

但 P4 §4 明文记录：**尚未实际注入故障、尚未生成故障副本、尚未运行模型**。这只是区分材料种类，不要求重做 P3/P4。计分前需按已定义案例生成实际输入，并检查公共执行与验收通道。P3 的部分人工核验状态也仍未完成。

### 第三项：应明示 D 作者知题；“因此 C 赢了自动更可信”只能条件成立

D 作者从公开任务卡知道六类故障是事实层面的已知条件；但知道题型并不等于已经读过完整私有答案，后者仍可控制和登记。

此外，P4 §0 **允许开发案例向模型公开并用于调提示词**，与旧 W1/Y4 的隔离要求不一致；C 的提示词作者也可能知道题目。没有实际上下文和开发记录时，不能断言 C 模型没见过答案。

Y4 现明确记录 D 作者及 C 开发/运行的曝光范围，计分阶段 C 使用新会话和冻结公共输入包。若曾用这六例调试，仍标记为开发曝光；新会话不抹去调试历史。只有确知信息优势偏向 D、D 实现合格且其他条件受控，C 的胜出才可称为胜过知题 baseline 的局部证据；统计把握与泛化主张不会因此自动增强。
