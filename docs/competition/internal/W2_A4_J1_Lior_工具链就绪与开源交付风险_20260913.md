## 4. 缺口清单（按对阶段 B 的影响排序）

- **GAP-1｜uv 缺失（阻塞本机门禁；有 CI 兜底）**：本机无法跑 `sandbox_runtime` 测试，dev_gate 持续 broken。纪律口径：这是**环境 FAIL，不得标 SKIP 变绿**。缓解：CI 双平台具备 uv，合并前门禁不失效；但 Lior 本地失去 sandbox 自证能力，B2/B4 期间每个 PR 都只能靠 CI 发现 sandbox 回归，反馈环变长。
- **GAP-2｜主仓 Python 版本漂移（3.12.10 vs 钉版 3.9.x）**：onboarding 明确 golden/hash 类测试版本敏感（"3.11 会假挂"）。当前 main_tests 在 3.12 下 pass，但**版本敏感证据不得声明以本机为准**；正式口径以 CI 的 3.9 环境为准，B4 前本机应并列安装 3.9.x 并固定 `AEDL_PYTHON`。
- **GAP-3｜KiCad / kicad-cli 缺失（B4 阻塞项，本周不阻塞）**：B4 的 pinned native environment、5 条 run_round、fresh 导出绑定无法在本机执行。好消息：B4 测试素材已就位——`tests/fixtures/repair_pr1/native/DC-01..05/`（fault.kicad_sch + repair_ops.json 各 5 组）已入库；akcli 自带的 `render` 不依赖 KiCad，但 `draw --apply` 后置 ERC 默认调用 kicad-cli（错误码 KICAD_CLI_MISSING=7）。
- **GAP-4｜akcli 仅有能力目录、二进制未钉（B2 前置决策项）**：仓库内只有 M1 期能力调查件 `notes/m1-evidence/akcli_capabilities.json`（akcli **0.21.0** / protocol v2，命令/退出码/错误码目录）与两次 check 记录；**无授权二进制、无路径、无 sha256 pin**。B2 任务卡的收死条件（pinned version/path/digest、一次写调用、applied+re-read+byte hash、固定快照回滚、无自动 fallback）要求 J1 先给授权版本与分发方式。另注：akcli 存在 BINFETCH_DOWNLOAD/BINFETCH_CHECKSUM（exit 7）取数路径，离线沙箱策略需一并定。
- **GAP-5｜D 盘空间 14.6 GB**：KiCad 全量 2–3 GB，叠加 uv 缓存与 B4 快照/夹具副本，余量吃紧；需决定安装盘与缓存目录策略。
