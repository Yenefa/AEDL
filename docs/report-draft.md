# 单 Agent 自主嵌入式研发系统 · 可行性调研报告

**项目编号**：project-027-autonomous-hardware-agent
**报告日期**：2026-08-24
**调研方式**：三轮联网核实（KiCad 自动化生态 / 仿真器板卡覆盖 / 器件供应链数据层）+ 本地工程经验库交叉验证
**确定性标注约定**：✅ = 已联网核实或属公认稳定事实；⚠️ = 待本机实测确认；❓ = 未深入核实，仅作背景参考

---

## 一、执行摘要

**核心结论：可行。2026 年做这个系统的时机显著优于两年前——全链路每一环都存在可脚本化、可 headless 运行的开源工具，且多个关键工具已原生面向 AI agent 设计。工程主战场不在"发明工具"，而在三件事：①把散装工具串成端到端流水线；②设计一套机器可判定的检查门禁（gate）体系；③建立诚实的证据分级与失败恢复纪律。**

推荐路线概要：

1. **底座**：不自研 agent runtime，基于 OpenCode/Claude Code + skills/MCP 集成现有生态（akcli-kicad、KiSkill、Wokwi CLI、Renode、jlcpcb-mcp 均自带 agent 集成入口）。
2. **EDA 主线**：KiCad 9/10 全 headless 流（原理图 JSON op-list 生成 → ERC → ngspice 断言 → freerouting 布线 → DRC → 渲染视觉自检 → 生产文件导出），生产文件投嘉立创。
3. **验证第一档**：无实体板交付。证据分三级显式标注——A 级（机器已验证）、B 级（一阶估计）、C 级（待实物验证）。绝不把 A 级证据包装成"实物可用"。
4. **起步域**：MCU 最小系统 + 外设的 2 层板；首选 ESP32-C3（行为仿真走 Wokwi，Release 级支持✅）与 STM32G0（走 Renode，官方文档含 stm32g0 平台✅）双 MCU 路线。
5. **节奏**：M0 门禁清单冻结 → M1 单点工具链本机实测 → M2 一块真实传感器板端到端全自动闭环 → M3 迭代循环与失败恢复强化 → M4 扩展器件域与复杂度。

主要风险（详见第九章风险登记册）：PCB 自动布局质量天花板、"所有可执行检查通过 ≠ 板子能工作"的固有边界、无 API 凭据期选型数据的新鲜度、迭代循环的 token 成本。

## 二、需求定义与系统边界

### 2.1 一句话需求

用户只描述想做什么（例："做一个电池供电的温湿度记录仪，BLE 上报"），系统自主完成技术调研、器件选型、电路设计、原理图、PCB、仿真、固件开发、调试和自动验证，反复修改直到所有可执行检查通过，交付可直接打板的生产文件 + 完整代码 + 采购清单。

### 2.2 输入/输出契约

| 方向 | 内容                                                                                                                                                               |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 输入 | 自然语言产品需求（功能、供电、接口、尺寸/成本约束可选）                                                                                                            |
| 输出 | ①嘉立创可下单 Gerber+钻孔文件；②BOM（含 LCSC 编号，装配库存已核实）；③贴片坐标文件；④完整固件源码+构建脚本；⑤测试报告（门禁逐项结果）；⑥设计决策记录（选型证据链） |

### 2.3 第一档明确不做什么

- ❌ 实物上电调试、烧录、示波器测量（需实体实验室）
- ❌ EMC 认证级验证、热老化、安规
- ❌ 高速信号（>50MHz）、射频匹配网络、精密模拟前端（<1mV 级）、电源完整性签核
- ❌ 4 层以上复杂叠层与阻抗控制板（首期限 2 层板）

### 2.4 交付物证据分级（贯穿全系统的铁律）

| 级别               | 含义                       | 典型来源                                                                               |
| ------------------ | -------------------------- | -------------------------------------------------------------------------------------- |
| **A · 机器已验证** | 有确定性的机器判定证据     | ERC/DRC JSON 报告、编译退出码、单元测试、ngspice 断言、Wokwi/Renode 行为断言           |
| **B · 一阶估计**   | 工具给出的近似评估，非签核 | SI/PI/EMC/热的闭式估算（kicad-mcp-pro 自述此类工具精度约 5–10%✅）、自动布局美观度评分 |
| **C · 待实物验证** | 只能上电后才知道           | 实际功耗、晶振起振、无线距离、量产良率                                                 |

每份交付报告必须按此分级标注每项结论。这条纪律的直接依据是本项目组在 Webots 机器人仿真项目中连续十二轮验证积累的证据边界经验：仿真运行证据永远不等于实体实测证据，材料口径必须分开表述。

## 三、三等建议摘要

### 3.1 乐观视角（为什么现在做正当时）

- **积木全部存在且活跃维护**✅：原理图自动化（akcli-kicad 于 2026-08 仍在发版）、EDA 检查（kicad-cli 原生 JSON 输出）、布线（freerouting）、固件仿真（Wokwi CLI 官方 GitHub Actions 集成 + 实验性 MCP 接口；Renode 提供 Robot Framework 测试与执行跟踪覆盖率）、器件数据（jlcpcb-mcp 无凭据即可查目录+实时库存价格+数据手册）。
- **多个工具原生为 AI agent 设计**✅：akcli-kicad 自述"a shell 就能驱动的 AI-native CLI"，输出带 schema 版本的 JSON 与机器可读修复提示；Wokwi CLI 内置 MCP server 模式。集成成本远低于两年前。
- **存在同构参考架构**✅：开源项目 oasis-firmware 已经在做"MCP 接口 + 数据手册摄取→元件行为模型 + 故障注入 + 多 MCU 仿真器统一框架"，验证了架构方向可行性。
- **差异化空间明确**✅：现有生态全是 copilot（人主导、AI 辅助），尚无成熟的开源 autopilot（一句话到打板文件全自动闭环）。

### 3.2 中立视角（成立的条件清单）

1. 范围收窄至"简单数字板"起步（MCU 最小系统+外设、2 层板），模拟/电源/射频另立专项。
2. "单 Agent"必须定义为：一个主控 agent 持有全部设计上下文 + 一组确定性工具进程，而非单次 LLM 调用。器件选型↔电路↔布局强耦合，拆多 agent 编排反而丢失一致性。
3. 系统的真正产品是**检查门禁套件**而非生成能力：LLM 提方案，每环节有机器可判定 gate，不达标带结构化错误重试。
4. 必须建一层器件数据库治理（目录快照 + 库存新鲜度策略 + Basic/Extended 优先级），这是决定选型可信度的脏活。
5. token 经济学需要专门设计：门禁反馈必须压缩成结构化错误清单回喂，禁止全量日志进上下文。

### 3.3 悲观视角（哪里会翻车）

1. **"所有可执行检查通过"≠ 板子能工作**。SPICE 与 DRC 抓不住 EMC/热/寄生参数；这是物理边界不是工程努力问题。系统诚实性完全依赖证据分级的严格执行。
2. **没有实体实验室，"调试"环节名存实亡**。第一档交付终点只能是"寄给你打样"。未来要闭环实物需投 HIL 台架（烧录器、治具、pyOCD/OpenOCD 自动化），接线仍需人工。
3. **PCB 自动布局质量天花板低**。freerouting 能过 DRC，但"过 DRC"与"好板"差距巨大。
4. **选型是最容易静默出错的环节**：停产料、封装映射错误、手册解析错引脚。LCSC 零售库存 ≠ JLC 贴片装配库存✅（社区文档明确区分两池），用错池子会导致下单缺料。
5. **token 成本失控风险**：多轮迭代单板设计可达数十万至上百万 token；无预算熔断机制时，单板设计成本可能超过物料成本数十倍。

## 六、系统架构设计

### 6.1 单 Agent 架构原则

1. **一个主控 agent 持有全部设计上下文**：规格表、选型决策、网络表、约束、失败历史都在同一会话上下文中流转，保证跨环节一致性。
2. **所有专业能力下沉为确定性工具进程**：ERC/DRC/SPICE/编译/仿真器都是带退出码与 JSON 输出的 CLI/MCP 工具，agent 只做决策与调度，不做裁判。
3. **agent 只信机器输出**：任何工具自报"成功"无效，以退出码+结构化报告为准（本项目组实测教训：subagent 曾自报依赖已安装实际装错环境）。
4. **门禁不过不出交付物**：任何 gate 失败 → 结构化错误回喂 agent 重试；迭代超预算 → 熔断并输出人工介入清单。

### 6.2 六阶段流水线与门禁位置

```
①需求解析 ──G0 规格完整性──► ②调研选型 ──G1 选型数据核验──►
③电路设计(akcli) ──G2 ERC / G3 SPICE 断言──►
④PCB(freerouting+kicad-cli) ──G4 DRC / G5 DFM 一阶 / G6 渲染视觉──►
⑤固件(ESP-IDF/PlatformIO) ──G7 编译 / G8 单测 / G9 行为断言(Wokwi/Renode)──►
⑥交付打包 ──G10 生产文件校验(Gerber 完整性/BOM 装配库存复核)──► 测试报告+证据分级标注
```

每道 gate 的失败输出都是结构化 JSON（错误码+定位+修复提示），agent 消费该清单决定修改动作。

### 6.3 可执行检查门禁总表（M0 冻结对象）

| Gate | 检查项         | 执行命令/来源                     | 通过标准                                   | 证据级 |
| ---- | -------------- | --------------------------------- | ------------------------------------------ | ------ |
| G0   | 规格完整性     | LLM 输出 vs 规格 Schema           | Schema 校验通过、无 TBD 字段               | A      |
| G1   | 选型可采购     | jlcparts 快照+jlcpcb-mcp          | 每料有 LCSC 编号、装配库存≥阈值、快照≤7 天 | A      |
| G2   | 原理图电气规则 | kicad-cli sch erc --format json   | 0 error（warning 白名单制）                | A      |
| G3   | 电路行为       | akcli sim / ngspice 断言集        | 全部断言通过（工作点/浪涌/去耦）           | A      |
| G4   | PCB 设计规则   | kicad-cli pcb drc --format json   | 0 violation（含嘉立创工艺定制规则）        | A      |
| G5   | 可制造性一阶   | kicad-mcp-pro DFM 族              | 无高危项；其余降级为 B 级备注              | B      |
| G6   | 渲染视觉自检   | 分层渲染 PNG + 几何/视觉检查      | 无丝印重叠/极性反/孤岛铜皮（误报白名单）   | B      |
| G7   | 固件编译       | idf.py build / pio run            | exit code 0 且 0 warning（-Werror）        | A      |
| G8   | 单元测试       | Unity/Ceedling 主机端             | 全过且覆盖率≥目标线                        | A      |
| G9   | 板级行为断言   | wokwi-cli 场景断言 或 renode-test | 串口预期序列全命中、超时内完成             | A      |
| G10  | 交付物完整性   | Gerber 文件清单比对+BOM 复扫      | 文件齐全、BOM 与原理图一致、装配库存终验   | A      |

### 6.4 失败恢复与证据治理

1. **迭代预算**：每 gate 设最大重试次数（建议 G2-G4 各 5 轮、G9 各 3 轮），超限熔断并生成人工介入报告。
2. **失败轮次独立保留**：每轮迭代的产物存时间戳目录，禁止被后续轮次覆盖（Webots 项目 D12 教训的直接复用）。
3. **退出码传播铁律**：所有包装脚本显式传播真实退出码，禁止末尾命令掩盖失败。
4. **保护资产哈希锁定**：输入规格表、器件快照等关键输入在流程开始时记录 SHA-256，交付时验证未被中途改写。
5. **增量重试**：gate 失败回喂仅含结构化违规列表与修复提示，禁止全量日志进上下文（token 经济学）。

## 十、结论与拍板点

**结论**：立项成立，按 M0→M4 推进。系统的护城河不是任何单一工具，而是：①门禁体系（机器可判定的"完成"定义）；②证据分级纪律（对用户诚实的交付）；③供应链数据治理（选型可信度）。

**需要大统领拍板的三个点**：

1. **M1 预算授权**：本机安装 KiCad（约几 GB）、Renode、Wokwi CLI、Python 包若干——是否放行安装？
2. **首板选题**：建议"ESP32-C3 温湿度记录仪"作为 M2 验证载体（BLE 上报、电池供电、传感器 I2C——覆盖电源/数字/模拟边缘案例），是否有更想先做的板子？
3. **Wokwi 商用条款**❓：若未来对外提供服务需核实其 CI 云仿真的商用许可；个人研发阶段免费额度足够。
