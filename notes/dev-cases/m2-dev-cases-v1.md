## 2. 案例

### DC-01　USB 差分对身份接反　【强制违规 · 必须检出】

- **注入**：交换 `/USB_DM` 与 `/USB_DP` 在 U1 侧的落点 —— 使 `/USB_DM -> U1.14`、`/USB_DP -> U1.13`。
- **依据**：F-U1-01（datasheet p11 §3）：`IO18/pin13 = USB_D-`、`IO19/pin14 = USB_D+`。乐鑫检查清单独立佐证。
- **期望系统报告**：`USB_DM` 落到 pin 14（IO19，手册身份为 USB_D+），`USB_DP` 落到 pin 13（IO18，手册身份为 USB_D−）——**信号身份与手册定义相反**。
- **期望修复**：把两条网络在 U1 侧的落点换回（`/USB_DM→U1.13`、`/USB_DP→U1.14`）。
- **受保护关系（修复不得改动）**：J1 侧连接（`J1.A6/B6`、`J1.A7/B7`）、R7/R8 的串联位置与阻值、其余 27 个网络。
- **判定**：检出且修复正确且无受保护关系变动 → PASS。只报"USB 有问题"而未指出身份反转 → 部分检出，按未通过记，并如实写明检出粒度。
- **备注**：这是 PIT-20260830-001 的原始事故形态。ERC 通过、DRC 通过、8 项板级评审通过时该缺陷同时存在——**任何仅依赖 ERC/DRC 的方案必然漏检**。

### DC-02　SHT30 ADDR 悬空 vs 固件写死 0x44　【跨视图 · 重点案例】

- **注入**：断开 `U2.2` 与 `/GND` 的连接，使 ADDR 悬空；固件保持 `0x44` 不变。
- **依据**：
  - F-U2-01（p8 引脚表 + p9 正文，**两处明文**）："The ADDR pin must not be left floating."
  - F-U2-02（p9 Table 8）：`0x44`(default) = ADDR 接 **logic low**；`0x45` = 接 **logic high**。
- **期望系统报告**：**两条独立结论都要报**——
  1. 硬件侧违反手册强制条款：ADDR 悬空；
  2. 跨视图不一致：固件假设 `0x44` 要求 ADDR 为 logic low，而硬件未提供确定电平 → 地址未定义。
- **期望修复**：`U2.2 → GND`（logic low），与固件 `0x44` 对齐。
- **受保护关系**：固件地址值 `0x44` 不得改动（改固件去迁就悬空硬件是错误修复方向）；U2 其余引脚连接。
- **判定**：只报硬件悬空、未指出与固件的不一致 → 部分检出。**若修复方式是改固件为 `0x45` → 判为错误修复**（ADDR 仍悬空，问题未解决）。
- **备注**：**本案例是 AEDL 相对竞品的核心差异点。** ERC 不理解传感器地址选择语义，DRC 只看几何；PCBSchemaGen / SchGen / CircuitLM 均只覆盖原理图层面，不跨到固件。

### DC-03　缺 USB 串联电阻　【建议项 · 措辞敏感】

- **注入**：移除 R7、R8，使 `/USB_DM_CONN` 与 `/USB_DM` 直连、`/USB_DP_CONN` 与 `/USB_DP` 直连。
- **依据**：F-U1-04 —— 乐鑫设计指南："It is recommended to reserve series resistors (initial value can be **22/33 Ω**)"。**措辞是 `recommended`**；U1 datasheet 原件中**未检索到**该条款。
- **期望系统报告**：USB 差分对未串接原厂**建议**的 22/33 Ω 串阻。
- **期望修复**：在两条 USB 线上各串入 22 Ω（与基线一致）。
- **判定口径（本案例最容易出错的地方）**：
  - 报为"**未采纳原厂建议**"→ 正确。
  - 报为"**违反数据手册强制要求**"→ **判为错误定性**，即使它同时给出了正确修复。理由：过度定性会在正式评测里产生假失败，污染判定。
  - 完全不报 → 漏检。

### DC-04　缺 GPIO9 外部上拉　【加固项 · 不得直接判 FAIL】

- **注入**：移除 R9，使 `/BOOT` 仅剩 `SW2.1` 与 `U1.8`。
- **依据**：
  - F-U1-05（p12 Table 4-1）：GPIO9 默认配置为 **Weak pull-up，Bit Value = 1**；
  - F-U1-06（p13 Table 4-3）：`GPIO9 = 1` 即 SPI boot mode（默认）。
- **期望系统报告**：GPIO9 的外部上拉缺失；**并明确指出芯片内部已有弱上拉，默认仍为 SPI boot**，因此该项属设计裕量问题（对抗按键漏电流、走线噪声、上电瞬态），不是手册强制项。
- **期望修复**：补 10 kΩ 上拉至 3V3（与基线一致）。
- **判定**：
  - 报为"缺少加固/裕量不足"并说明内部弱上拉 → 正确。
  - **直接判 FAIL 且称"违反手册要求"→ 判为错误定性。**
  - 若系统主动说明"内部弱上拉使默认值成立、是否需要外部上拉取决于 BOOT 按键电路"→ 视为高质量输出，单独记录。

### DC-05　缺 EN 电容　【强制项与建议项共存 · 分级考察】

- **注入**：移除 C5，`/EN` 仅剩 `R3.2`、`SW1.1`、`U1.2`。
- **依据**：
  - F-U1-02（datasheet p11，**强制**）：`Note: Do not leave the EN pin floating.`
  - F-U1-03（设计指南，**建议**）：`advised to add an RC delay circuit at the CHIP_EN pin`，推荐 `R = 10 kΩ, C = 1 μF`。
- **期望系统报告**：EN 仍经 R3 上拉、**并未悬空**（强制条款 F-U1-02 未被违反）；缺失的是**建议**的 RC 延时中的 C 分量，影响上电/复位时序裕量。
- **期望修复**：补 1 µF 至 GND（与基线一致）。
- **判定**：
  - 正确区分"未违反强制条款、缺的是建议项"→ 正确。
  - **报为"EN 悬空"→ 判为事实错误**（R3 仍在，EN 未悬空）。这是本案例的主要陷阱。
  - 报为"违反手册强制要求"→ 错误定性。

### DC-06　U3 资料不足　【必须拒绝修复】

- **注入**：无需注入。使用当前真实状态——U3 = ME6211C33R5G（SOT-353），`datasheet_manifest.json` 标 `BLOCKED_POWER_THERMAL`。
- **依据**（P3 §6）：
  - V20 版给出 **250 mW @ 25°C** 封装耗散硬边界；
  - 实际耗散 **0.310 W**（150 mA 持续）/ **0.6415 W**（345 mA WiFi TX 峰值），**均超上限**；
  - **V20 未提供厂家 θJA** → 无法核算结温。
- **期望系统报告**：功率超出封装边界；**并明确指出缺少 θJA，因此无法完成结温核算** → 输出 `BLOCKED`（资料不足），**不得输出 PASS，也不得给出确定性的换料结论**。
- **期望行为**：**拒绝自动修复，转人工。**
- **判定**：
  - 输出 BLOCKED 并说明缺失的具体资料项 → **正确，本案例的 PASS 条件就是"正确地拒绝"**。
  - 直接给出"换成 AMS1117 即可"→ **判为越界**：AMS1117 的 θJA 随铺铜从 46 到 >90 °C/W 变化，未做本板布局核算不能下结论（见 `docs/u3_route_b_selection_proposal_v1.md`）。
  - 引用第三方"常见 θJA"数值代签 → **判为严重错误**（ADR-005 明令禁止）。
  - 报 PASS 或不报 → 误放行，最严重。

## 3. 汇总

| ID | 类型 | 期望结论 | 主要陷阱 |
|---|---|---|---|
| DC-01 | 强制违规 | 检出身份反转 + 正确换回 | 只报"USB 有问题"不算检出 |
| DC-02 | 跨视图不一致 | 硬件违规 **+** 与固件不一致，两条都报 | 改固件为 0x45 = 错误修复方向 |
| DC-03 | 建议项缺失 | 报"未采纳建议" | 报成"违反强制要求" |
| DC-04 | 加固项缺失 | 报裕量问题 + 说明内部弱上拉 | 直接判 FAIL |
| DC-05 | 建议项缺失（强制项未违反） | 区分两级 | **误报"EN 悬空"** |
| DC-06 | 资料不足 | **正确地拒绝** | 越界给换料结论 / 引二手 θJA |

**6 例中有 4 例（DC-03/04/05/06）的主要考察点是"不过度报告"。** 这是刻意的：过度定性在正式评测里产生假失败，与漏检同样污染判定，而多数方案只防漏检。
