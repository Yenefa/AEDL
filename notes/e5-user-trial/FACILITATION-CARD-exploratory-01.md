## 1. 任务是什么

CH340C USB-转串口板，**含一个已知缺陷**：USB 数据线 D+/D− 在 CH340C 一侧接反（DC-01 类，源 `notes/dev-cases/m2-dev-cases-v1.md`）。与 M2 本体无关，符合协议 §4「用不同的板子」。

- 给参与者：`boards/exploratory-01/participant/usb_serial_adapter.kicad_sch`，**每人一份独立副本**
- **不给**：`facilitator/` 下任何文件（答案卡、正确版原理图、校验脚本）

⚠️ **本板 ERC 实测 0 违规 0 警告**（ANSWER_KEY §3.2）。参与者跑 ERC 全绿是**预期结果**，不是他的工具坏了——不要因此暗示"再看看别处"。这恰好是访谈 Q5 所问的情形。

## 2. 开场词（照念，不要加工）

> 「这是一块 USB 转串口的小板子，**里面有一个已知的问题**。请你用**自己平时的方法**去找它——工具随便用，网也可以上。找到了就告诉我问题在哪、为什么。时间上限 20 分钟，中途想放弃随时说。我全程只记录，不会提示。」

**不得说**：缺陷类型、在哪个器件、有几个问题、「仔细看 USB 部分」之类的引导。

## 3. 计时（字段定义照抄协议 §5.3）

| 字段 | 定义 |
|---|---|
| `timer_start` | **拿到文件**的时刻（协议 §5.2「从拿到文件到给出结论」；不是"打开成功"的时刻） |
| `timer_end` | 给出**最终结论**（说出问题 / 明确放弃）的时刻 |
| pause | 去厕所、接电话等**单列**；净用时 = end − start − Σpause |
| 上限 | **20 分钟（本卡设定）**。到点叫停，记 `not_found` 并在备注写「到时叫停，非自主放弃」 |

> 若打开文件本身出了问题（KiCad 版本、环境），**计时照常走**，把耽误的时间记成 pause 并在备注写明——不要偷偷把起点后移。

## 4. `hint_events[]` 怎么记（协议 §5.3，四个字段一条都不能少）

每条：`{who: participant|facilitator|tool, what: 自由文本, at: mm:ss, phase: pre_conclusion|post_conclusion}`

| 情形 | 记法 |
|---|---|
| 参与者自己上网查手册 / 翻数据手册 | `who=participant`（协议 §5.3 明文：这类计入 hint_events） |
| 他跑 ERC、导网表，工具给出输出 | `who=tool` |
| 问「这个功能在 KiCad 哪里」「怎么导出网表」 | **不算 hint** → 计入 `ops_questions`（操作性支持） |
| 主持人说了任何与**电路内容**有关的话 | `who=facilitator`，同时 `interventions` +1 —— **应当避免**，一旦发生必须记 |

三场之间口径必须一致，否则 exploratory 数据不可比。另需记 `stuck_points`（卡点原文）与 `verbatim`（口头原话）——**这两项是逐字内容，只进私有归档**。

## 5. `outcome` 判定

协议 §5.3 的通用定义 + ANSWER_KEY §4 对本板的具体化：

| outcome | 本板判据（ANSWER_KEY §4） |
|---|---|
| `found_exact` | 明确指出 **USB D+/D− 在 CH340C 侧接反**（等价表述亦可：「UD+ 接到了 D−」「差分对反了」） |
| `found_partial` | 指出 USB 数据线有问题，但**未定位到「接反」**（例：「USB 那里好像不对」「D+/D− 要检查一下」） |
| `not_found` | 给出结论但**未涉及 USB 数据线**；或到 20 分钟上限仍未给出 |
| `abandoned` | 主动放弃，**原因必填** |

### 5.1 三个预期干扰项：如实记录，但**不影响 outcome**

按 ANSWER_KEY §4.1，以下说法都**不是本板缺陷**，出现时记为额外观察即可，不要因此判 `found_partial`：

- 「USB 线上少了 22 Ω 串阻」——CH340C 典型应用电路不加，属建议级
- 「CH340C 好多引脚没接」——已加 no-connect 标记，典型设计如此
- 「屏蔽壳直接接地不妥」——简单板上常见，非缺陷

> 干扰项本身是有价值的数据：它反映检查习惯与知识边界，编码时照录（协议 §3.1）。

主持人可用 `facilitator/ANSWER_KEY.md` 核对，但**全程不得让参与者看到**。
