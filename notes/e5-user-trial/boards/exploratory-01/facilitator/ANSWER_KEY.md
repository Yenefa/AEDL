## 2. 板子

**CH340C USB 转串口适配器** —— 学生项目中极常见的设计，与 M2 本体无关。

| 位号 | 器件 | 作用 |
|---|---|---|
| J1 | USB-C 16P（USB 2.0） | 输入 |
| U1 | CH340C | USB 转 UART（内置振荡器，无需晶振） |
| R1 / R2 | 5.1 kΩ | CC1 / CC2 下拉（USB-C 设备端识别） |
| C1 | 10 µF | VBUS 储能 |
| C2 | 100 nF | U1 VCC 去耦 |
| C3 | 100 nF | U1 V3（VCC = 5 V 时的标准接法） |
| J2 | 1×4 排针 | UART 输出：GND / RXD / TXD / +5V |

标题栏为中性的「CH340C USB-Serial Adapter」，文件名为中性的 `usb_serial_adapter.kicad_sch` ——
**均不含任何提示缺陷存在的字样**。

## 3. 缺陷（唯一一个）

### 3.1 是什么

**USB 数据线 D+ / D− 在 CH340C 一侧接反**（DC-01 类：差分对身份接反，强制违规）。

| 网络 | 连接到 | 应当连接到 |
|---|---|---|
| `USB_D+` | J1.A6、J1.B6、**U1.6（UD−）** | J1.A6、J1.B6、**U1.5（UD+）** |
| `USB_D-` | J1.A7、J1.B7、**U1.5（UD+）** | J1.A7、J1.B7、**U1.6（UD−）** |

后果：USB 枚举失败，电脑无法识别该设备。

### 3.2 为什么 ERC 查不出来

两个引脚**都已连接**，只是连到了彼此的网络上。ERC 检查的是「有没有连、电气类型是否冲突」，
不检查「D+ 是否连到了 D+」。**本板 ERC 实测 0 违规、0 警告**（见 §5）。

**这正是访谈 Q5「有没有 ERC 全绿但板子还是错的情况」所问的情形。**

### 3.3 怎样在图上发现

U1 左侧，**名为 `UD+` 的 5 号引脚旁边贴着 `USB_D-` 标签**；**名为 `UD-` 的 6 号引脚旁边贴着 `USB_D+`**。
对照引脚名与网络名即可发现。

### 3.4 正确修法

交换 U1.5 与 U1.6 上的两个标签（或等价地，把 J1 的 D+ 接到 U1.5、D− 接到 U1.6）。
参考正确版见 `usb_serial_adapter_correct.kicad_sch`。

## 4. 判分（按协议 §5.3 schema 的 outcome 四态）

| outcome | 判定标准 |
|---|---|
| **found_exact** | 明确指出 **USB D+/D− 在 CH340C 侧接反**（或等价表述：「UD+ 接到了 D−」「差分对反了」） |
| **found_partial** | 指出 USB 数据线有问题，但**未定位到「接反」**（例：「USB 那里好像不对」「D+/D− 要检查一下」） |
| **not_found** | 给出结论但未涉及 USB 数据线 |
| **abandoned** | 主动放弃 |

同时按 §5.3 记录：净用时、用了什么工具、hint_events、卡在哪、口头原话。

### 4.1 预期干扰项（**不计入** found_exact，但**如实记录**）

| 参与者可能说 | 事实 | 处理 |
|---|---|---|
| 「USB 线上少了 22 Ω 串联电阻」 | CH340C 的典型应用电路不加串阻；属**建议级**讨论（参见 DC-03 的分级），非本板目标缺陷 | 记为额外观察，不影响 outcome |
| 「CH340C 那么多引脚没接」 | CTS / DSR / RI / DCD / DTR / RTS / R232 及 NC 7、8 均已加 no-connect 标记，典型设计如此 | 同上 |
| 「屏蔽壳直接接地不妥」 | 简单板上 SHIELD 直接接地很常见，非缺陷 | 同上 |

> 干扰项的出现本身是有价值的数据：它反映参与者的检查习惯与知识边界，编码时照录（协议 §3.1）。

## 6. 已知限制

- **非缺陷部分的正确性依据 CH340C 典型应用电路（通用知识），CH340C 数据手册未冻结入库** ——
  未达到 P3 器件事实目录那样的逐页人工核验标准。「除一处缺陷外其余正确」的主张以此为界。
  若需与 P3 同等标准，须先冻结 CH340C 数据手册并逐项核对 V3、UD+/UD−、调制解调引脚的推荐接法。
- **仅原理图，无 PCB。** exploratory 任务按协议 §4 为「含一个已知缺陷的 KiCad 原理图」，与此一致。
- **缺陷类型单一（DC-01）。** 本板只校准「差分对身份接反」这一类的难度；C2 若使用其他缺陷类型，
  其难度不能由本板数据直接推定。
- **ERC 结论限于默认规则。** 若参与者修改了 ERC 规则集，其 ERC 结果可能不同。
