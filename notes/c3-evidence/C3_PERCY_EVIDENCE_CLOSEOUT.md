## 1. evidence level

### 1.1 先解决一个真问题：`L1/L2/L3` 在本仓库有三套互不兼容的含义

实测（`git grep`）：`L1` 129 处、`L3` 70 处、`L2` 63 处、`L4` 18 处、`L0` 16 处。逐处看语境，至少落在三套不同的尺子上：

| 尺子 | 出处 | `L2` 在这套里是什么意思 |
|---|---|---|
| **目检难度分级** | `notes/m2-evidence-reset/M2目检提示词-多模态AI.md` | 中等难度的目检观察项 |
| **authority 证明强度** | `CONTROL_PLANE` 相关讨论：`L1 declared / L2 git provenance / L3 external` | 由 git 溯源证明的权限 |
| **Y4 事实披露层级** | Issue #68 的 D1 裁定：`L1 事实 + L1.5 策略子集 + L2 操作` | 指向具体修复操作的信息（**不得**入公共包） |

**风险**：最终报告若直接写「L2」，评审读到的是哪一套取决于他先看了哪一节。这不是洁癖问题——**三套尺子里有一套（Y4 披露层级）的 L2 表示"这东西不能公开"**，与另两套的"中等强度/中等难度"含义相反。

**处置（本文件采用）**：报告中的证据等级**不复用 `L` 前缀**，改用下面 §1.2 的独立词表。三套既有 `L` 尺子在各自文档内保留原样，但**引用时必须带限定词**（「目检难度 L2」「authority L2」「披露层级 L2」），不得裸写。

### 1.2 报告用的证据等级词表（四级，保守方向）

| 等级 | 判据 | 报告里允许的措辞 |
|---|---|---|
| **E-VERIFIED** | 有可复现的机器产物（门禁输出、测试、哈希、CI run 号），**且**本仓库外的人按记载步骤可重跑 | 「已验证」「实测」 |
| **E-OBSERVED** | 有一次性观测记录（截图、单次运行日志、host 归档），可核但**不可由外部独立重跑** | 「观测到」「本机实测」——**必须同时写明不可外部复现** |
| **E-DECLARED** | 只有人的声明或文档记载，无机器产物 | 「据记载」「按声明」——**不得**写成「已验证」 |
| **TO_VERIFY** | 未核实 | 保持 `TO_VERIFY`，**不得**因为「大概率是对的」而上浮 |

**三条硬规则**：

1. **不上浮**（红线 3）。等级只能在补充证据后由**人工**上调，且必须在文件里留下上调的日期与依据；AI 不得自行上调。
2. **单次观测不叫验证。** 资格调用、单次 run、单机 dev_gate 结果一律 `E-OBSERVED`，即使全绿。
3. **声明的诚实性不换等级。** 一份诚实的自报（例如 `token_budget_status = NOT_VERIFIED`）仍是 `E-DECLARED`——诚实使它可用，不使它变成验证。

### 1.3 已知会落在低等级的几项（提前登记，免得报告期被动）

| 项 | 等级 | 原因 |
|---|---|---|
| C/D 预算相同 | `E-DECLARED` | harness 不数 token，由适配器自管（`token_budget_status = NOT_VERIFIED`） |
| C 臂通路可行性 | `E-OBSERVED` | 资格调用是**单次**观测，非 p95（`G9-AUTHORIZATION.json` 原文亦如此写） |
| 本机 dev_gate | `E-OBSERVED` | 单机环境；权威门禁为 CI 双平台（同 #70 §5 Q4 的提问） |
| Y4-003 / DC-04 的 A_dry | `E-OBSERVED` + 例外标注 | 评分者对该例有先验结果曝光；且判据的公共依据句不被冻结字节满足（Issue #68） |
| E5 第二段 | 可能 `NOT_RUN` | 前置 Y2+Y3（协议 §5.4），未达成则如实标未执行 |

> **方法限制（如实声明）**：以上按**文件角色**分类，不是逐行语义判定。C / D / E / F 四类在动手前仍须逐条确认。A / B 两类的分类可由文件性质直接确定。

### 2.2 两条分流纪律

1. **历史记录不回填。** `docs/compliance/ai-usage/*`、`DECISIONS.md`、W1 任务卡与评审笔记里的 `TO_VERIFY` 记的是**当时**的事实，改写它们等于伪造时间线。同 `ai-usage/README.md`「不改别人条目」。需要更新的，**另起补记**。
2. **区分「待验项过期」与「待验理由过期」。** 两者处置不同——前者销账，后者只改理由、`TO_VERIFY` 保留。典型例见下。

## 3. E5 limitations（预登记）

**为什么现在写**：这些局限**全部由设计决定**，不依赖任何尚未采集的数据。等结果出来再写，读者无法分辨哪些是诚实披露、哪些是挑着写的。

### 3.1 协议自带（`e5-protocol-v1.md` §0 / §6，逐条引用）

1. **两段之间隔了时间。** 第一段（访谈）与第二段（两 arm 对照）不同场次。协议 §0 原话：「这是方法学上的让步，必须在报告里明写，不能装作是同一场次的交错对照。」
2. **v1 的「基线任务」不成立，已降级。** 第一段的计时任务与第二段任务不同场次、不同题、且第二段无 baseline 复测，**不构成合法对照**；v1.1 起只作 exploratory，**不得进入 E5 对照统计**（§0、§4、§6）。
3. **n = 3–5 只支持初步可用性判断。** 协议 §6 原话：「不能推断广泛市场效果——报告里必须写这句。」
4. **外部用户数据与团队自测分开报告**，不合并统计（§6）。
5. **失败与中途放弃必须保留**，不得只报成功案例（§6）。
