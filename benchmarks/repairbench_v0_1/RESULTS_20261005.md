## 未跑项与原因（如实）

`baseline_generic` / `aedl_contract` 两个 LLM 臂**未运行**。原因：本机唯一存在的
`ARK_API_KEY`（env 长度 46）对配置端点返回 **HTTP 401 Unauthorized**，对 RES-012 登记的
DeepSeek host 亦无有效凭据。按 ADR-022 决策 5 第 2 条，Agent 不自行动用他人账户或付费额度，
因此**没有跑出来的数字一律不写、不推测、不用「预计」代替**。

**因此当前不存在「AEDL 优于 baseline」的任何结论。** 一条都没有。

## 这次运行暴露的两个真问题

### 1. 冻结合同断言了器件**值**，却没断言**存在**（DC-03 / DC-04 / DC-05 全军覆没）

合同里 `ESP32_GPIO9_PULLUP` 写的是：

```json
"components": { "R9": { "value": "10k" } }
```

但这三集的故障恰恰是 **R9 / R7+R8 / C5 整个器件不存在**。机械臂据合同推出
「给 R9.1 加 `+3V3` 标签」，akcli 依法**拒绝**（exit 6，`pin reference 'R9' matches no
placed component`）。这是合同的**完备性缺口**，不是机械臂的缺陷：

> 合同能完整指定「某个已存在器件的某个脚应该接哪个网」，但**不能指定「这个器件应该被放上去」**——
> 缺 footprint、缺坐标、缺「必须存在」这一位。

影响：合同作为**修复说明书**目前只覆盖「改网名」类故障，覆盖不了「补器件」类故障。
这正是 v0.1 只有 5 集、单一板子时最容易漏掉的东西。

### 2. 按合同机械加标签会**合并已命名网络**（DC-01 结构性错，且被回归护栏抓到）

机械臂对 DC-01 推出两条标签，akcli 接受并写入，但结果是：

```text
net USB_DM: 期望 ['R8.2','U1.13']  实际 ['R7.2','R8.2','U1.13','U1.14']
net USB_DP: 期望 ['R7.2','U1.14']  实际 []
```

即 **DP 与 DM 被并成同一网**。原因：`add_net_label` 落在已属某网的脚上时，akcli 会按
strict-nets 语义处理；本次调用**没有加 `--strict-nets`**，于是命名网络被合并。

这一条是本次运行最有价值的产出：**Regression Guard + structural 两层同时把它抓住了**
（`structural: fail`，成员集合不符）。也就是说这套 benchmark 不只会给分，还能**指出失败原因**。

同时它给出一个明确的工程要求：**任何按合同推导标签的臂，都必须带 net-split 守卫**
（即 akcli 的 `--strict-nets`，或等价的事前拓扑差分检查），否则「修 A 弄坏 B」。

## 为什么 DC-01 的 primary 也是 FAIL

primary 要求 `USB_POLARITY_AND_SERIES` 由 fail 转 pass；该规则同时断言
`R7.1/R7.2/R8.1/R8.2/U1.13/U1.14` 六个脚的网名。机械臂只按「当前与合同不符」逐脚加标签，
在 DP/DM 已被并网的情况下无法让该规则整体转 pass。这与 oracle 的做法差别在于：
oracle 的答案还包含 2 条 `delete_object`，先清掉错误连线再重建。

## 结论（严格限于本次实测）

1. benchmark **可用**：有不可通吃的对照（noop 0/5）、有可解性对照（oracle 5/5）、
   三层指标都能给出方向性诊断。
2. 冻结合同作为修复说明书**不完备**：补器件类故障无法从合同推导（3/5 集）。
3. 按合同机械改网名**必须**配 net-split 守卫，否则会并网（DC-01 实测）。
4. **没有**任何 LLM 对比结果；**没有**任何「优于 baseline」的主张。
5. n=5、单板、netlist 作用域、离线。ADR-023 要求 20–30 集 / 3–5 故障族，v0.1 远未达到。
