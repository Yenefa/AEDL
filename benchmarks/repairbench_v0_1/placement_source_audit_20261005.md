# DC-01..DC-05 的「补器件」故障能否由冻结源推导修复 —— 定位审计

> 日期：2026-10-05 ｜ 结论：**不能**。且原因是坐标体系不一致，不是「缺一个字段」那么简单。

## 审计的问题

首轮实测（`EVID-20261005-001`）发现：冻结合同只断言器件的**值**（`R9: {value: 10k}`），
不断言**存在**，也没有坐标，因此 DC-03 / DC-04 / DC-05 这三集「补器件」故障
无法由合同推导修复（确定性臂 1/5，akcli 依法拒绝 `pin reference 'R9' matches no
placed component`）。

于是要问：这些信息能否从**别的冻结源**合法补上？

## 逐源核查（全部实测）

| 冻结源 | 器件存在性 | lib_id / value / footprint | 坐标 | 可用？ |
| --- | --- | --- | --- | --- |
| `src/hardware/m2-board/intent_v1.json` | 有（23 个器件） | **有**（R7/R8/R9/C5 齐全） | **无** | 部分可用 |
| `src/hardware/m2-board/m2_board.kicad_pcb` | 有（21 个 footprint） | 有 | **有，但坐标系对不上** | **不可用** |
| `gates/contracts/m2_schematic_contract_v1.json` | 不断言 | 只有 value | 无 | 不可用 |
| `tests/fixtures/.../repair_ops.json`（答案键） | 有 | 有 | 有 | **求解臂禁止读取** |

## 关键发现：PCB 坐标系与 DC 夹具坐标系不一致

用**锚定解析**（在相邻 `(footprint` 起点之间切片，杜绝跨块串读）读出冻结 PCB：

| 器件 | 冻结 PCB 位置 | 答案键 `acceptance_v1.json` 位置 |
| --- | --- | --- |
| R7 | (23.30, 18.00) mm | (218.44, 193.04) mm |
| R8 | (23.30, 19.50) mm | (276.86, 193.04) mm |
| R9 | (1.45, 22.50) mm | (34.29, 257.81) mm |
| C5 | (1.45, 13.50) mm | (267.97, 36.83) mm |

两者**相差近一个数量级**，不是同一套坐标。

佐证：DC-02 夹具的 sheet UUID 是 `a1dbe1c3-f1f0-496b-b2c7-2a432ea67147`，
其元件坐标在 154–277 mm 量级；而 M2 PCB 的 R9 在 1.45 / 22.5 mm。
**DC-01..DC-05 不是 M2 板自身坐标系的产物**，而是一套独立合成/派生的 schematic。

（首轮我曾用固定 2500 字符窗口做正则抽取，那会跨进相邻 footprint；
本次改为锚定切片后结论不变、但**方法**才是可信的。）

## 结论

1. **器件存在性 + lib_id/value/footprint 可以合法补上**——冻结 intent 里有，且这是
   设计意图真源，不是答案键。
2. **坐标不能补**。冻结 PCB 的坐标系与夹具不一致，用它摆放器件会得到「装上去了但
   位置完全错误」的结果——那比修不好更糟。
3. 因此 **DC-03 / DC-04 / DC-05 在「求解臂不得读答案键」的前提下不可解**。
   这不是实现不够努力，是**题目本身缺一个坐标真源**。

## 由此得到的两条决策（不是能力主张）

- **要么**给 v0.1 换一批**自带布局意图**的夹具（每集携带自己的器件坐标真源，
  与冻结合同同源、同坐标系），补器件类故障才可能进入可解范围；
- **要么**把 v0.1 的故障族明确限定为**纯连通性类**（改网名 / 接悬空脚 / 删多余连线），
  并在 `episodes_v1.json` 里写明「补器件类故障不在 v0.1 范围内」，而不是让它们
  以 0 分的形式混在分数里。

两者都比「让求解臂去读答案键」诚实。
